This tutorial builds provider use case 2 from nothing: a repository with a library of API description fragments and two projects, `orders` and `payments`, each implementing its own contract, sharing one fragment, and each building against a versioned, verified copy of its contract.
Every file and every command below was run exactly as shown, with API-Only Publisher 0.2.0 and API-Only Subscriber 0.1.0.

It assumes you know how to design an API in OpenAPI, how a bundler such as https://redocly.com/docs/cli/[Redocly CLI ↗] resolves `$ref`s into one document, and how a multi-project Gradle build is laid out.

[#before-you-start]
== Before you start

[cols="1,2", options="header"]
|===
|You need |Version

|Node.js and npm
|Node.js `^22.14.0`, `^24.10.0` or `>=26.0.0`

|Java
|21 or newer

|Gradle
|8 or newer, through the repository's wrapper
|===

In the Publisher's terms, each contract is a *target*.
Here the targets are `orders` and `payments`, and each project is named after the target it implements.
Use your own contracts' names wherever those appear.

[#step-1]
== Step 1: Create the library and pin the Publisher

.contracts/package.json
[source,json]
----
{
  "name": "contracts",
  "private": true,
  "scripts": {
    "apionly": "api-only-publisher"
  }
}
----

[source,console]
----
cd contracts
npm install --save-dev --save-exact @arc-e-tect/api-only-publisher@0.2.0
----

Add `node_modules/` and `build/` to the repository's `.gitignore`, and commit `package.json` and `package-lock.json`.

.Considerations
* **The library does not need to be a Gradle project.**
It is a directory the Gradle build reads, with its own Node.js installation.
* **Run the Publisher only through the script**: `npm run apionly -- <command>`.
It runs the version `package-lock.json` pins, and nothing else.
`npx api-only-publisher` is not this package; npx would look that unscoped name up on the public registry.

[#step-2]
== Step 2: Write the fragments

Each contract has a bundle root: its table of contents, holding the `info` block and `$ref`s to fragments.

.contracts/specs/openapi/bundles/orders.yaml
[source,yaml]
----
openapi: 3.1.1
info:
  title: Orders API
  version: 0.0.0
  license:
    name: MIT
    identifier: MIT
servers:
  - url: https://api.orders.test
security: []
paths:
  /orders:
    $ref: ../paths/Orders.yaml
----

.contracts/specs/openapi/paths/Orders.yaml
[source,yaml]
----
get:
  operationId: listOrders
  summary: List the orders.
  responses:
    '200':
      description: The orders.
      content:
        application/json:
          schema:
            type: array
            items:
              type: string
    '400':
      $ref: ../components/common/BadRequest.yaml
----

`payments.yaml` and `Payments.yaml` follow the same pattern, with `Payments API`, `https://api.payments.test`, `/payments` and `listPayments`.
Both contracts reference the same shared fragment:

.contracts/specs/openapi/components/common/BadRequest.yaml
[source,yaml]
----
description: The request was not valid.
----

.Considerations
* **`info.version` is a placeholder.**
The build overwrites it with the contract's real version, so `0.0.0` is conventional; it has to be present.
* **`components/common/` is a convention**, not a requirement.
It says "not specific to one contract", which is what a reviewer needs to know before changing a fragment there.

[#step-3]
== Step 3: Choose the lint rules

.contracts/.redocly.yaml
[source,yaml]
----
extends:
  - recommended
----

.Considerations
* **Keep this file outside `contracts/specs/`.**
The lint also checks that every YAML file under the fragments' root is referenced by some contract, and a Redocly configuration inside that root is a YAML file nothing references.

[#step-4]
== Step 4: Give each contract a version

Beside each bundle root, a version file named after the target:

.contracts/specs/openapi/bundles/orders.bundle.properties
[source,properties]
----
# The version of the orders contract.
version=1.0.0
----

.contracts/specs/openapi/bundles/payments.bundle.properties
[source,properties]
----
# The version of the payments contract.
version=1.0.0
----

.Considerations
* **Each contract is versioned on its own.**
A change to `orders` alone raises only `orders`.
* **Major is for a breaking change, minor for an additive one, patch for anything else.**
* **The file holds a release version.**
A pre-release is cut when publishing, with `--pre-release rc.1`.

[#step-5]
== Step 5: Describe the build in `apionly.yaml`

.contracts/apionly.yaml
[source,yaml]
----
schemaVersion: 1

sources:
  root: specs
  openapi: openapi

defaults:
  openapi:
    lint: .redocly.yaml
    outputName: openapi.yaml

build:
  staging: build/staging
  dist: build/dist

reports:
  lint: build/reports/lint

toolchain:
  redocly: "@redocly/cli@2.52.0"

channels:
  file:
    directory: build/publish
    clean: true

targets:
  orders:
    openapi:
      bundle: bundles/orders.yaml
  payments:
    openapi:
      bundle: bundles/payments.yaml
----

[cols="1,3", options="header"]
|===
|Key |What it says

|`sources`
|The fragments are under `contracts/specs/openapi/`; bundle paths are relative to it.

|`defaults.openapi`
|The lint rules, and the bundled document's name.
Keep `openapi.yaml`: the Subscriber looks for exactly that name.

|`build`, `reports`
|Everything the Publisher writes goes under `contracts/build/`.

|`toolchain.redocly`
|The exact Redocly CLI version the Publisher runs.

|`channels.file`
|Publishing writes versioned archives to `contracts/build/publish/`.
`clean: true` keeps only each contract's latest version, because this directory is a build output, not a record of releases.

|`targets`
|One entry per contract.
|===

Try it, from `contracts/`:

[source,console]
----
npm run apionly -- build
npm run apionly -- lint
----

[#step-6]
== Step 6: Declare the projects, and the version each implements

.settings.gradle
[source,groovy]
----
rootProject.name = 'shop'
include 'orders', 'payments'
----

.orders/gradle.properties
[source,properties]
----
# The version of the orders contract this project implements.
apiContractVersion=1.0.0
----

.payments/gradle.properties
[source,properties]
----
# The version of the payments contract this project implements.
apiContractVersion=1.0.0
----

.Considerations
* **A project is named after the contract it implements.**
That convention keeps the wiring in step 8 the same for every project.
If your projects are named differently, give each a `apiContractTarget` property and read that instead of `project.name`.
* **The version a project implements is its own decision.**
It lives in the project's own `gradle.properties`, so adopting a new contract version is a change to that project only.

[#step-7]
== Step 7: Write the contract tests first

Each project gets the same test.
It passes only when that project's contract is on its classpath, at the version the project implements.

.orders/src/test/java/com/example/orders/ApiContractTest.java
[source,java]
----
package com.example.orders;

import org.junit.jupiter.api.Test;

import java.io.IOException;
import java.io.InputStream;
import java.nio.charset.StandardCharsets;

import static org.junit.jupiter.api.Assertions.assertNotNull;
import static org.junit.jupiter.api.Assertions.assertTrue;

class ApiContractTest {

    @Test
    void theContractThisProjectImplementsIsOnTheClasspath() throws IOException {
        try (InputStream document = getClass().getResourceAsStream("/openapi.yaml")) {
            assertNotNull(document, "openapi.yaml is not on the test classpath");
            String text = new String(document.readAllBytes(), StandardCharsets.UTF_8);
            String version = System.getProperty("apiContractVersion");
            assertTrue(text.contains("version: " + version),
                "openapi.yaml does not declare version " + version);
        }
    }
}
----

Copy it to `payments/src/test/java/com/example/payments/`, with the package changed.

Before step 8 wires anything, `./gradlew test` fails for both projects with `openapi.yaml is not on the test classpath`, once the test dependencies below are in place.

[#step-8]
== Step 8: Wire every project from the root build

.build.gradle
[source,groovy]
----
import org.gradle.api.services.BuildService
import org.gradle.api.services.BuildServiceParameters

plugins {
    id 'base'
    id 'com.arc-e-tect.api-only-subscriber' version '0.1.0' apply false
}

// ---------------------------------------------------------------------------
// The API contracts. Each project builds and publishes the contract it
// implements from contracts/, and subscribes to it through the file channel.
// ---------------------------------------------------------------------------

def contracts = file('contracts')
def npm = System.getProperty('os.name').toLowerCase().contains('windows') ? 'npm.cmd' : 'npm'

// Every Publisher run rebuilds the same staging tree in contracts/build, so no
// two runs may overlap, even with --parallel.
abstract class ApiOnlyPublisherRuns implements BuildService<BuildServiceParameters.None> {}
def publisherRuns = gradle.sharedServices.registerIfAbsent('apiOnlyPublisherRuns', ApiOnlyPublisherRuns) {
    maxParallelUsages = 1
}

def installApiOnlyPublisher = tasks.register('installApiOnlyPublisher', Exec) {
    group = 'api-only'
    description = 'Installs the API-Only Publisher at the version contracts/package-lock.json pins.'
    workingDir contracts
    inputs.files(new File(contracts, 'package.json'), new File(contracts, 'package-lock.json')).withPropertyName('manifests')
    outputs.file(new File(contracts, 'node_modules/.package-lock.json')).withPropertyName('installation')
    commandLine npm, 'ci', '--no-audit', '--no-fund'
}

def lintApiContracts = tasks.register('lintApiContracts', Exec) {
    group = 'verification'
    description = 'Lints every contract, and fails on a fragment no contract references.'
    dependsOn subprojects.collect { "${it.path}:buildApiContract" }
    usesService publisherRuns
    workingDir contracts
    inputs.dir(new File(contracts, 'specs')).withPropertyName('specification')
    inputs.dir(new File(contracts, 'build/dist')).withPropertyName('bundles')
    outputs.dir(new File(contracts, 'build/reports/lint')).withPropertyName('reports')
    commandLine npm, 'run', '--silent', 'apionly', '--', 'lint'
}
tasks.named('check') { dependsOn lintApiContracts }

subprojects {
    apply plugin: 'java'
    apply plugin: 'com.arc-e-tect.api-only-subscriber'

    repositories {
        mavenCentral()
    }

    dependencies {
        testImplementation platform('org.junit:junit-bom:6.1.3')
        testImplementation 'org.junit.jupiter:junit-jupiter'
        testRuntimeOnly 'org.junit.platform:junit-platform-launcher'
    }

    tasks.named('test') {
        useJUnitPlatform()
        systemProperty 'apiContractVersion', project.findProperty('apiContractVersion')
    }

    // A project implements the contract that has its name.
    def target = project.name

    def buildApiContract = tasks.register('buildApiContract', Exec) {
        group = 'api-only'
        description = "Bundles, stamps and lints the ${target} contract."
        dependsOn installApiOnlyPublisher
        usesService publisherRuns
        workingDir contracts
        inputs.dir(new File(contracts, 'specs')).withPropertyName('specification')
        inputs.files(new File(contracts, 'apionly.yaml'), new File(contracts, 'package-lock.json')).withPropertyName('configuration')
        outputs.dir(new File(contracts, "build/dist/${target}")).withPropertyName('bundle')
        commandLine npm, 'run', '--silent', 'apionly', '--', 'build', '--target', target
    }

    def publishApiContract = tasks.register('publishApiContract', Exec) {
        group = 'api-only'
        description = "Publishes the ${target} contract to the file channel in contracts/build/publish."
        dependsOn buildApiContract
        usesService publisherRuns
        workingDir contracts
        inputs.dir(new File(contracts, "build/dist/${target}")).withPropertyName('bundle')
        outputs.dir(new File(contracts, "build/publish/${target}")).withPropertyName('archive')
        commandLine npm, 'run', '--silent', 'apionly', '--', 'publish', '--target', target, '--channel', 'file'
    }

    apiOnlySubscriber {
        channel {
            type = 'file'
            directory = new File(contracts, 'build/publish').path
        }
        // At the version apiContractVersion in this project's gradle.properties declares.
        subscribe(target)
    }

    tasks.withType(com.arc_e_tect.gradle.apionly.subscriber.FetchApiSpecTask).configureEach {
        dependsOn publishApiContract
    }
}
----

[cols="1,3", options="header"]
|===
|Task |What it does

|`installApiOnlyPublisher`
|`npm ci` in `contracts/`, once for the whole build.

|`<project>:buildApiContract`
|Bundles, stamps and lints that project's contract, from the whole of `contracts/specs/`, because a shared fragment can change any contract.

|`<project>:publishApiContract`
|Packs the contract and writes it to `contracts/build/publish/<target>/<version>/`.

|`<project>:fetchApiSpec<Target>`, from the Subscriber
|Reads the archive at the project's `apiContractVersion`, verifies it, unpacks it into the project's `build/api-spec/`, and records it in the project's `apionly.lock`.

|`<project>:verifyApiSpec<Target>`, from the Subscriber
|Checks the fetched documents against `apionly.lock`, as part of `check`.

|`lintApiContracts`
|Lints every contract once more, and fails on a YAML file under `contracts/specs/` that no contract references, as part of `check`.
|===

Run the build:

[source,console]
----
./gradlew check
----

[source]
----
> Task :installApiOnlyPublisher
> Task :orders:buildApiContract
> Task :payments:buildApiContract
> Task :orders:publishApiContract
> Task :orders:fetchApiSpecOrders
Subscribed to orders 1.0.0
> Task :orders:verifyApiSpecOrders
> Task :orders:test
> Task :lintApiContracts
> Task :payments:publishApiContract
> Task :payments:fetchApiSpecPayments
Subscribed to payments 1.0.0
> Task :payments:verifyApiSpecPayments
> Task :payments:test

BUILD SUCCESSFUL
----

Both contract tests pass.
Run `./gradlew check --parallel` again, and every contract task is `UP-TO-DATE`.

.Considerations
* **The shared build service** is what lets Gradle run the projects in parallel.
Every Publisher run works in the same `contracts/build/staging/` directory, so two must never overlap; the service lets only one run at a time.
* **Gradle's configuration cache** works with this build unchanged.
* **A contract no project implements**, such as a whole-landscape view marked `publish: false`, is still linted by `lintApiContracts`, so it has to be built first: add a task that runs `build --target <name>` in `contracts/`, and make `lintApiContracts` depend on it.

== Step 9: Commit the lockfiles

The first fetch wrote an `apionly.lock` in each project:

.orders/apionly.lock
[source]
----
format 1

target orders
version 1.0.0
channel file
sha256 266f7c64549d9eebb5c410eda00bb489d19eab5f22e78a49f2cd2f36585476b1 openapi.yaml
----

Commit both.
From now on, each records exactly which contract its project builds against.

[#step-10]
== Step 10: See the guards fail, once each

Undo each change before the next.

=== A change to a shared fragment

Change `BadRequest.yaml`, commit nothing, and ask the Publisher which contracts that change reaches, from `contracts/`:

[source,console]
----
npm run apionly -- changed --since HEAD --quiet
----

[source]
----
orders
payments
----

Run `./gradlew check --continue` without raising any version:

[source]
----
> Task :orders:fetchApiSpecOrders FAILED
> Task :payments:fetchApiSpecPayments FAILED
> the published contract for 'orders' 1.0.0 is not the one recorded in apionly.lock:
> the published contract for 'payments' 1.0.0 is not the one recorded in apionly.lock:
----

Both contracts changed, so both need a new version.
Raise `version` to `1.0.1` in both `.bundle.properties` files and `apiContractVersion` to `1.0.1` in both projects, and run `./gradlew check`:

[source]
----
Updated orders from 1.0.0 to 1.0.1
Updated payments from 1.0.0 to 1.0.1

BUILD SUCCESSFUL
----

Commit the fragment, the four version changes and both lockfiles together.

=== A fragment that nothing references

Add `contracts/specs/openapi/components/common/Unused.yaml` without referencing it, and run `./gradlew check`:

[source]
----
> Task :lintApiContracts FAILED
Error: 1 fragment(s) not reachable from any target, so nothing lints them:
  openapi/components/common/Unused.yaml
Reference each one from a target's bundle, or delete it.
----

=== Only one of the two versions raised

Raise only a project's `apiContractVersion`, or only its contract's `version`, and its fetch fails naming the version it looked for and the version that is published:

[source]
----
> no archive for 'orders' 1.2.0 at .../contracts/build/publish/orders/1.2.0/orders-1.2.0.tgz.
  Published versions of 'orders': 1.1.0.
  Publish 1.2.0 first, or subscribe to a version that is published.
----

[#step-11]
== Step 11: Run it in CI

CI needs Node.js as well as Java, and runs the same `./gradlew check`.
In GitHub Actions:

..github/workflows/build.yml
[source,yaml]
----
name: build

on:
  push:
  pull_request:

permissions:
  contents: read

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v7
      - uses: actions/setup-node@v6
        with:
          node-version: 24
      - uses: actions/setup-java@v5
        with:
          distribution: temurin
          java-version: 21
      - uses: gradle/actions/setup-gradle@v6
      - name: Build, lint and test every project
        run: ./gradlew check --parallel
      - name: The lockfiles are committed
        run: git diff --exit-code -- '*/apionly.lock'
      - name: Upload the lint reports
        if: always()
        uses: actions/upload-artifact@v7
        with:
          name: api-lint-reports
          path: contracts/build/reports/lint/
----

.Considerations
* **The lockfile step** fails a build that adopted a new contract version without committing the updated `apionly.lock`.
* **Running only the changed projects** is possible, but every project's build reads all of `contracts/specs/`, so a change to a shared fragment has to trigger every project.
Build everything unless the build is genuinely too slow.

[#what-you-have]
== What you have now

* One library that owns every fragment, with shared fragments defined once.
* Contracts built from it in every build, each with its own version.
* A committed lockfile per project that says exactly which contract it builds against.
* A build that fails on an unreferenced fragment, on a changed contract under an unchanged version, and on versions that disagree.

[#watch-for]
== What to watch for

* **A hand edit to a project's `build/api-spec/` does not survive the next build.**
`./gradlew check` fetches again before verifying, and the fetch restores the published document.
`./gradlew verifyApiSpec` on its own is what reports such an edit.
* **A project implements one contract.**
Each project subscribes to the contract it is named after, and a second contract gets a project of its own.
link:../../../reference/run-book.adoc#one-contract-per-project[The run-book →] says why.
* **The contract's version is not the project's version.**
A release of `orders` that does not touch its contract does not change the contract's version.
