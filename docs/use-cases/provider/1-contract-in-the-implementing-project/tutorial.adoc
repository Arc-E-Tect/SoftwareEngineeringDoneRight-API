This tutorial builds provider use case 1 from nothing: one Gradle project that implements an `orders` API, owns that API's OpenAPI description, and builds against a versioned, verified copy of it.
Every file and every command below was run exactly as shown, with API-Only Publisher 0.2.0 and API-Only Subscriber 0.1.0.

It assumes you know how to design an API in OpenAPI, how a bundler such as https://redocly.com/docs/cli/[Redocly CLI ↗] resolves `$ref`s into one document, and how a Gradle project is laid out.

[#before-you-start]
== Before you start

[cols="1,2", options="header"]
|===
|You need |Version

|Node.js and npm
|Node.js `^22.14.0`, `^24.10.0` or `>=26.0.0`

|Java
|21 or newer

|Gradle
|8 or newer, through the project's wrapper

|A Gradle project
|With the `java` plugin applied, called `orders-service` below
|===

The API is called `orders` throughout.
In the Publisher's terms that name is the *target*: it names the contract, its archive, its lockfile entry, and the Gradle tasks that handle it.
Use your own API's name wherever `orders` appears.

[#what-you-build]
== What you will build

[source]
----
orders-service/
├── package.json                    Pins the API-Only Publisher
├── package-lock.json
├── apionly.yaml                    What the Publisher builds, and where it puts it
├── .redocly.yaml                   The lint rules
├── gradle.properties               apiContractVersion: the version this project implements
├── build.gradle                    Builds, publishes, lints and fetches the contract
├── apionly.lock                    Generated by the build, committed
└── src/
    ├── main/api/openapi/
    │   ├── bundles/orders.yaml     The bundle root
    │   ├── bundles/orders.bundle.properties   The contract's version
    │   ├── paths/Orders.yaml
    │   └── components/schemas/OrderList.yaml
    └── test/java/com/example/orders/ApiContractTest.java
----

[#step-1]
== Step 1: Pin the Publisher

Create `package.json` at the project root:

.package.json
[source,json]
----
{
  "name": "orders-service-api",
  "private": true,
  "scripts": {
    "apionly": "api-only-publisher"
  }
}
----

Install the Publisher as an exact dev dependency:

[source,console]
----
npm install --save-dev --save-exact @arc-e-tect/api-only-publisher@0.2.0
----

Add `node_modules/` and `build/` to `.gitignore`, and commit `package.json` and `package-lock.json`.

.Considerations
* **Run the Publisher only through the script**: `npm run apionly -- <command>`.
It runs the version `package-lock.json` pins, and nothing else.
`npx api-only-publisher` is not this package; npx would look that unscoped name up on the public registry.
* **Pin exactly.**
A range would let the documents change because an upstream release happened, with nothing in your project having changed.

[#step-2]
== Step 2: Write the fragments

The bundle root is the contract's table of contents.
It holds the `info` block and `$ref`s to the fragments:

.src/main/api/openapi/bundles/orders.yaml
[source,yaml]
----
openapi: 3.1.1
info:
  title: Orders API
  version: 0.0.0
  license:
    name: MIT
    identifier: MIT
servers:
  - url: https://api.orders.test
security: []
paths:
  /orders:
    $ref: ../paths/Orders.yaml
----

.src/main/api/openapi/paths/Orders.yaml
[source,yaml]
----
get:
  operationId: listOrders
  summary: List the orders.
  responses:
    '200':
      description: The orders.
      content:
        application/json:
          schema:
            $ref: ../components/schemas/OrderList.yaml
    '400':
      description: The request was not valid.
----

.src/main/api/openapi/components/schemas/OrderList.yaml
[source,yaml]
----
type: array
items:
  type: string
----

.Considerations
* **`info.version` is a placeholder.**
The build overwrites it with the contract's real version, from the file in step 4, so `0.0.0` is conventional.
It has to be present: a document without an `info.version` cannot be stamped, and the build says so.
* **`$ref` paths are relative to the file that holds them.**
* **How you split the fragments is up to you.**
The Publisher only needs one bundle root per contract.
A contract that is still one hand-written document can be that bundle root on its own, `$ref`ing nothing.

[#step-3]
== Step 3: Choose the lint rules

.`.redocly.yaml`, at the project root
[source,yaml]
----
extends:
  - recommended
----

The Publisher lints every document it builds with this file, using Redocly CLI.
`recommended` is Redocly's own baseline; narrow or widen it as you would for any Redocly project.

.Considerations
* **Keep this file outside `src/main/api/`.**
The lint also checks that every YAML file under the fragments' root is referenced by the contract, because a fragment nothing references is never linted.
A Redocly configuration inside that root is a YAML file nothing references, and the lint reports it.

[#step-4]
== Step 4: Give the contract a version

Beside the bundle root, create the version file.
Its name is the target's name followed by `.bundle.properties`:

.src/main/api/openapi/bundles/orders.bundle.properties
[source,properties]
----
# The version of the orders contract. Major for a breaking change, minor for an
# additive one, patch for anything else. Change it with the fragments it describes.
version=1.0.0
----

.Considerations
* **The version lives with the fragments** and changes in the same commit as them, so it is reviewed with the change it describes.
* **It holds a release version.**
A pre-release, such as `1.1.0-rc.1`, is cut when publishing, with `--pre-release rc.1`, and never written into this file.

[#step-5]
== Step 5: Describe the build in `apionly.yaml`

.apionly.yaml
[source,yaml]
----
schemaVersion: 1

sources:
  root: src/main/api
  openapi: openapi

defaults:
  openapi:
    lint: .redocly.yaml
    outputName: openapi.yaml

build:
  staging: build/api-only/staging
  dist: build/api-only/dist

reports:
  lint: build/api-only/reports/lint

toolchain:
  redocly: "@redocly/cli@2.52.0"

channels:
  file:
    directory: build/api-only/publish
    clean: true

targets:
  orders:
    openapi:
      bundle: bundles/orders.yaml
----

[cols="1,3", options="header"]
|===
|Key |What it says

|`sources.root`, `sources.openapi`
|The fragments are under `src/main/api/openapi/`.
A bundle path is relative to that directory.

|`defaults.openapi.lint`
|The lint rules from step 3.

|`defaults.openapi.outputName`
|The bundled document's file name.
Keep `openapi.yaml`: the Subscriber looks for exactly that name.

|`build.staging`, `build.dist`
|Where the Publisher works and where it writes the bundled document.
Both inside `build/`, so nothing generated lives under `src/`, and `clean` removes it.

|`reports.lint`
|Where the lint reports are written.

|`toolchain.redocly`
|The exact Redocly CLI version the Publisher runs.

|`channels.file`
|Publishing writes a versioned archive to `build/api-only/publish/`.
`clean: true` keeps only the version published last, because this directory is a build output, not a record of releases.

|`targets.orders`
|The contract, and its bundle root.
|===

Try it:

[source,console]
----
npm run apionly -- build
npm run apionly -- lint
----

`build/api-only/dist/orders/openapi.yaml` is now one self-contained document with `info.version: 1.0.0`, and both commands succeed.

.Considerations
* An AsyncAPI description goes in the same way: `sources.asyncapi`, `defaults.asyncapi.outputName: asyncapi.yaml`, `toolchain.asyncapi`, and an `asyncapi.bundle` under the target.
The contract's version file then covers both documents.

[#step-6]
== Step 6: Declare the version the project implements

.gradle.properties
[source,properties]
----
# The version of the orders contract this project implements.
apiContractVersion=1.0.0
----

The Subscriber reads `apiContractVersion` as the version to fetch.
It is deliberately a second number, separate from the version the contract declares: the contract says which version it *is*, and the project says which version it *implements*.
Here both change together, and the build checks that they agree.

[#step-7]
== Step 7: Write the contract test first

Before any wiring exists, write the test that proves it works.
It passes only when the bundled document is on the classpath, at the version the project implements.

.build.gradle
[source,groovy]
----
plugins {
    id 'java'
    id 'com.arc-e-tect.api-only-subscriber' version '0.1.0'
}

repositories {
    mavenCentral()
}

dependencies {
    testImplementation platform('org.junit:junit-bom:6.1.3')
    testImplementation 'org.junit.jupiter:junit-jupiter'
    testRuntimeOnly 'org.junit.platform:junit-platform-launcher'
}

tasks.named('test') {
    useJUnitPlatform()
    // The contract version this project implements, for ApiContractTest.
    systemProperty 'apiContractVersion', providers.gradleProperty('apiContractVersion').get()
}
----

.src/test/java/com/example/orders/ApiContractTest.java
[source,java]
----
package com.example.orders;

import org.junit.jupiter.api.Test;

import java.io.IOException;
import java.io.InputStream;
import java.nio.charset.StandardCharsets;

import static org.junit.jupiter.api.Assertions.assertNotNull;
import static org.junit.jupiter.api.Assertions.assertTrue;

class ApiContractTest {

    @Test
    void theContractThisProjectImplementsIsOnTheClasspath() throws IOException {
        try (InputStream document = getClass().getResourceAsStream("/openapi.yaml")) {
            assertNotNull(document, "openapi.yaml is not on the test classpath");
            String text = new String(document.readAllBytes(), StandardCharsets.UTF_8);
            String version = System.getProperty("apiContractVersion");
            assertTrue(text.contains("version: " + version),
                "openapi.yaml does not declare version " + version);
        }
    }
}
----

Run it, and watch it fail:

[source,console]
----
./gradlew test
----

[source]
----
ApiContractTest > theContractThisProjectImplementsIsOnTheClasspath() FAILED
    org.opentest4j.AssertionFailedError at ApiContractTest.java:17
----

.Considerations
* **This test is your evidence that the wiring works**, now and after every change to the build.
Keep it.
* If your project already uses JUnit 5, keep its version; the test works unchanged on JUnit 5 and 6.

[#step-8]
== Step 8: Wire the contract into the build

Append to `build.gradle`:

.build.gradle (continued)
[source,groovy]
----
// ---------------------------------------------------------------------------
// The API contract. The Publisher builds and publishes it to a directory in
// build/, and the Subscriber fetches it from there, verifies it against
// apionly.lock, and puts it on the classpath.
// ---------------------------------------------------------------------------

def npm = System.getProperty('os.name').toLowerCase().contains('windows') ? 'npm.cmd' : 'npm'

def installApiOnlyPublisher = tasks.register('installApiOnlyPublisher', Exec) {
    group = 'api-only'
    description = 'Installs the API-Only Publisher at the version package-lock.json pins.'
    inputs.files('package.json', 'package-lock.json').withPropertyName('manifests')
    outputs.file('node_modules/.package-lock.json').withPropertyName('installation')
    commandLine npm, 'ci', '--no-audit', '--no-fund'
}

def buildApiContract = tasks.register('buildApiContract', Exec) {
    group = 'api-only'
    description = 'Bundles, stamps and lints the orders contract.'
    dependsOn installApiOnlyPublisher
    inputs.dir('src/main/api').withPropertyName('specification')
    inputs.files('apionly.yaml', 'package-lock.json').withPropertyName('configuration')
    outputs.dir('build/api-only/dist/orders').withPropertyName('bundle')
    commandLine npm, 'run', '--silent', 'apionly', '--', 'build', '--target', 'orders'
}

def publishApiContract = tasks.register('publishApiContract', Exec) {
    group = 'api-only'
    description = 'Publishes the orders contract to the file channel in build/api-only/publish.'
    dependsOn buildApiContract
    inputs.dir('build/api-only/dist/orders').withPropertyName('bundle')
    outputs.dir('build/api-only/publish/orders').withPropertyName('archive')
    commandLine npm, 'run', '--silent', 'apionly', '--', 'publish', '--target', 'orders', '--channel', 'file'
}

def lintApiContract = tasks.register('lintApiContract', Exec) {
    group = 'verification'
    description = 'Lints the contract, and fails on a fragment nothing references.'
    dependsOn buildApiContract
    inputs.dir('src/main/api').withPropertyName('specification')
    inputs.dir('build/api-only/dist').withPropertyName('bundles')
    outputs.dir('build/api-only/reports/lint').withPropertyName('reports')
    commandLine npm, 'run', '--silent', 'apionly', '--', 'lint'
}
tasks.named('check') { dependsOn lintApiContract }

apiOnlySubscriber {
    channel {
        type = 'file'
        directory = file('build/api-only/publish').path
    }
    // At the version apiContractVersion in gradle.properties declares.
    subscribe('orders')
}

// The fetch reads what publishApiContract writes.
tasks.named('fetchApiSpecOrders') { dependsOn publishApiContract }
----

[cols="1,3", options="header"]
|===
|Task |What it does

|`installApiOnlyPublisher`
|`npm ci`, so the build runs exactly the Publisher `package-lock.json` pins.
Skipped when neither `package.json` nor `package-lock.json` changed.

|`buildApiContract`
|Bundles the fragments, stamps the version from `orders.bundle.properties`, and lints the result.
Skipped when no fragment, `apionly.yaml` or pinned tool changed.

|`publishApiContract`
|Packs the bundled document with a `manifest.json` of its SHA-256 hashes, and writes it to `build/api-only/publish/orders/<version>/`.

|`lintApiContract`
|Lints again, and fails on a YAML file under `src/main/api/` that the contract does not reference.
Part of `check`.

|`fetchApiSpecOrders`, from the Subscriber
|Reads the archive at `apiContractVersion`, checks every document against its manifest, unpacks it into `build/api-spec/orders/`, and records the version and hashes in `apionly.lock`.
`processResources` depends on it, so the document reaches the classpath.

|`verifyApiSpecOrders`, from the Subscriber
|Checks the documents on disk against `apionly.lock`.
Part of `check`.
|===

Run the build:

[source,console]
----
./gradlew check
----

[source]
----
> Task :installApiOnlyPublisher
> Task :buildApiContract
> Task :publishApiContract
> Task :fetchApiSpecOrders
Subscribed to orders 1.0.0
> Task :verifyApiSpecOrders
> Task :verifyApiSpec
> Task :processResources
> Task :test
> Task :lintApiContract
> Task :check

BUILD SUCCESSFUL
----

`ApiContractTest` passes now.
Run `./gradlew check` again and every contract task is `UP-TO-DATE`.

.Considerations
* **Gradle's configuration cache** works with this build unchanged.
* **On Windows**, the `npm` variable resolves to `npm.cmd`.
* **With the Kotlin DSL**, the same tasks translate directly: `tasks.register<Exec>("buildApiContract") { ... }`, and `apiOnlySubscriber { channel { type.set("file") } }`.

[#step-9]
== Step 9: Commit the lockfile

The first fetch wrote `apionly.lock`:

.apionly.lock
[source]
----
# apionly.lock -- the published contracts this project builds against.
# Generated by the Arc-E-Tect API-Only Subscriber. Commit it; do not edit it.
# Run `verifyApiSpec` to check that what is on disk still matches.
format 1

target orders
version 1.0.0
channel file
sha256 2958789f19b662c9a58a4b7f2ae88c3ca2c9d017373d4d564b59c0af4e987213 openapi.yaml
----

Commit it.
From now on, the lockfile says exactly which contract this project builds against, and the build refuses anything else.

[#step-10]
== Step 10: See the guards fail, once each

Each guard below is worth triggering once, on purpose, so you recognise its message later.
Undo each change before the next.

=== A fragment that nothing references

Add `src/main/api/openapi/components/schemas/Unused.yaml` without referencing it, and run `./gradlew check`:

[source]
----
> Task :lintApiContract FAILED
Error: 1 fragment(s) not reachable from any target, so nothing lints them:
  openapi/components/schemas/Unused.yaml
Reference each one from a target's bundle, or delete it.
----

=== A fragment that changed under an unchanged version

Change `summary: List the orders.` in `Orders.yaml`, change no version, and run `./gradlew check`:

[source]
----
> Task :fetchApiSpecOrders FAILED
> the published contract for 'orders' 1.0.0 is not the one recorded in apionly.lock:
    - openapi.yaml differs
        locked:    2958789f19b662c9a58a4b7f2ae88c3ca2c9d017373d4d564b59c0af4e987213
        published: b64ef2062048bf06b910e90a8725953dfe0c73897643b362a65888f1e9a297b4

  1.0.0 was published to the file channel again, with different content. Find out why before accepting this: if the change was intended, publish it as a new version and subscribe to that; if it was not, publish the specifications the locked contract came from again. Delete the entry from apionly.lock only to re-lock deliberately.
----

A version names one set of documents, so a changed document needs a new version.

=== The change done properly

Keep the changed summary, raise `version` in `orders.bundle.properties` to `1.1.0` and `apiContractVersion` in `gradle.properties` to `1.1.0`, and run `./gradlew check`:

[source]
----
Updated orders from 1.0.0 to 1.1.0

BUILD SUCCESSFUL
----

`apionly.lock` now records `version 1.1.0` and the new hash.
Commit the fragment, both versions and the lockfile together.

=== Only one of the two versions raised

Raise only `apiContractVersion`, to `1.2.0`, and run `./gradlew check`:

[source]
----
> Task :fetchApiSpecOrders FAILED
> no archive for 'orders' 1.2.0 at .../build/api-only/publish/orders/1.2.0/orders-1.2.0.tgz.
  Published versions of 'orders': 1.1.0.
  Publish 1.2.0 first, or subscribe to a version that is published.
----

Raising only the contract's version gives the same message the other way round.

[#step-11]
== Step 11: Run it in CI

CI needs Node.js as well as Java, and runs the same `./gradlew check`.
In GitHub Actions:

..github/workflows/build.yml
[source,yaml]
----
name: build

on:
  push:
  pull_request:

permissions:
  contents: read

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v7
      - uses: actions/setup-node@v6
        with:
          node-version: 24
      - uses: actions/setup-java@v5
        with:
          distribution: temurin
          java-version: 21
      - uses: gradle/actions/setup-gradle@v6
      - name: Build, lint and test
        run: ./gradlew check
      - name: The lockfile is committed
        run: git diff --exit-code -- apionly.lock
      - name: Upload the lint reports
        if: always()
        uses: actions/upload-artifact@v7
        with:
          name: api-lint-reports
          path: build/api-only/reports/lint/
----

.Considerations
* **The lockfile step** fails a build that adopted a new contract version without committing the updated `apionly.lock`.
* **Pin the actions** to commit SHAs if your organisation requires it.

[#what-you-have]
== What you have now

* A contract built from fragments, linted, and published as a versioned archive on every build.
* A committed lockfile that says exactly which contract the project builds against.
* A build that fails on an unreferenced fragment, on a changed contract under an unchanged version, and on versions that disagree.
* A test that proves the contract reaches the code.

[#watch-for]
== What to watch for

* **A hand edit to `build/api-spec/orders/openapi.yaml` does not survive the next build.**
`./gradlew check` fetches again before verifying, and the fetch restores the published document.
`./gradlew verifyApiSpec` on its own is what reports such an edit.
Change the fragments, never the fetched document.
* **`manifest.json` is on the classpath next to `openapi.yaml`.**
It records the contract's version and hashes, which a deployed artifact can usefully carry.
* **The contract's version is not the project's version.**
A release of the service that does not touch the contract does not change the contract's version.
