This tutorial builds client use case 2 from nothing: a repository, `shop`, with a library of API description fragments for an `orders` and a `payments` API, sharing one fragment, and a project, `storefront`, that calls both APIs and builds against a versioned, verified copy of each contract.
Every file and every command below was run exactly as shown, with API-Only Publisher {api-only-publisher-version} and API-Only Subscriber {api-only-subscriber-version}.

It assumes you know how to design an API in OpenAPI, how a bundler such as https://redocly.com/docs/cli/[Redocly CLI ↗] resolves `$ref`s into one document, and how a multi-project Gradle build is laid out.

[#step-1]
== Step 1: Create the library

.contracts/package.json
[source,json]
----
{
  "name": "contracts",
  "private": true,
  "scripts": {
    "apionly": "api-only-publisher"
  }
}
----

[source,console,subs="attributes+"]
----
cd contracts
npm install --save-dev --save-exact @arc-e-tect/api-only-publisher@{api-only-publisher-version}
----

Add `node_modules/`, `build/` and `.gradle/` to the repository's `.gitignore`.

.contracts/specs/openapi/bundles/orders.yaml
[source,yaml]
----
openapi: 3.1.1
info:
  title: Orders API
  version: 0.0.0
  license:
    name: MIT
    identifier: MIT
servers:
  - url: https://api.orders.test
security: []
paths:
  /orders:
    $ref: ../paths/Orders.yaml
----

.contracts/specs/openapi/paths/Orders.yaml
[source,yaml]
----
get:
  operationId: listOrders
  summary: List the orders.
  responses:
    '200':
      description: The orders.
      content:
        application/json:
          schema:
            type: array
            items:
              type: string
    '400':
      $ref: ../components/common/BadRequest.yaml
----

.contracts/specs/openapi/components/common/BadRequest.yaml
[source,yaml]
----
description: The request was not valid.
----

`payments.yaml` and `Payments.yaml` follow the same pattern, with `Payments API`, `https://api.payments.test`, `/payments`, `listPayments` and `List the payments.`, and reference the same `BadRequest.yaml`.

.contracts/specs/openapi/bundles/orders.bundle.properties
[source,properties]
----
# The version of the orders contract.
version=1.0.0
----

`payments.bundle.properties` is the same, for `payments`.

.contracts/.redocly.yaml
[source,yaml]
----
extends:
  - recommended
----

.contracts/apionly.yaml
[source,yaml]
----
schemaVersion: 1

sources:
  root: specs
  openapi: openapi

defaults:
  openapi:
    lint: .redocly.yaml
    outputName: openapi.yaml

build:
  staging: build/staging
  dist: build/dist

reports:
  lint: build/reports/lint

toolchain:
  redocly: "@redocly/cli@2.52.0"

channels:
  file:
    directory: build/publish
    clean: true

targets:
  orders:
    openapi:
      bundle: bundles/orders.yaml
  payments:
    openapi:
      bundle: bundles/payments.yaml
----

.Considerations
* **The library does not need to be a Gradle project.**
It is a directory the root build reads, with its own Node.js installation.
* **Run the Publisher only through the script**: `npm run apionly -- <command>`; `npx api-only-publisher` is not this package.

[#step-2]
== Step 2: Build and publish every contract from the root build

.settings.gradle
[source,groovy]
----
rootProject.name = 'shop'
include 'storefront'
----

.build.gradle
[source,groovy,subs="attributes+"]
----
import org.gradle.api.services.BuildService
import org.gradle.api.services.BuildServiceParameters

plugins {
    id 'base'
    id 'com.arc-e-tect.api-only-subscriber' version '{api-only-subscriber-version}' apply false
}

// ---------------------------------------------------------------------------
// The API contracts. The root build builds and publishes every contract in
// contracts/ to the file channel in contracts/build/publish, and lints the
// whole library. Projects subscribe to what is published there.
// ---------------------------------------------------------------------------

def contracts = file('contracts')
def apiContracts = ['orders', 'payments']
def npm = System.getProperty('os.name').toLowerCase().contains('windows') ? 'npm.cmd' : 'npm'

// Every Publisher run rebuilds the same staging tree in contracts/build, so no
// two runs may overlap, even with --parallel.
abstract class ApiOnlyPublisherRuns implements BuildService<BuildServiceParameters.None> {}
def publisherRuns = gradle.sharedServices.registerIfAbsent('apiOnlyPublisherRuns', ApiOnlyPublisherRuns) {
    maxParallelUsages = 1
}

def installApiOnlyPublisher = tasks.register('installApiOnlyPublisher', Exec) {
    group = 'api-only'
    description = 'Installs the API-Only Publisher at the version contracts/package-lock.json pins.'
    workingDir contracts
    inputs.files(new File(contracts, 'package.json'), new File(contracts, 'package-lock.json')).withPropertyName('manifests')
    outputs.file(new File(contracts, 'node_modules/.package-lock.json')).withPropertyName('installation')
    commandLine npm, 'ci', '--no-audit', '--no-fund'
}

def buildApiContracts = apiContracts.collect { target ->
    def buildApiContract = tasks.register("buildApiContract${target.capitalize()}", Exec) {
        group = 'api-only'
        description = "Bundles, stamps and lints the ${target} contract."
        dependsOn installApiOnlyPublisher
        usesService publisherRuns
        workingDir contracts
        inputs.dir(new File(contracts, 'specs')).withPropertyName('specification')
        inputs.files(new File(contracts, 'apionly.yaml'), new File(contracts, 'package-lock.json')).withPropertyName('configuration')
        outputs.dir(new File(contracts, "build/dist/${target}")).withPropertyName('bundle')
        commandLine npm, 'run', '--silent', 'apionly', '--', 'build', '--target', target
    }
    tasks.register("publishApiContract${target.capitalize()}", Exec) {
        group = 'api-only'
        description = "Publishes the ${target} contract to the file channel in contracts/build/publish."
        dependsOn buildApiContract
        usesService publisherRuns
        workingDir contracts
        inputs.dir(new File(contracts, "build/dist/${target}")).withPropertyName('bundle')
        outputs.dir(new File(contracts, "build/publish/${target}")).withPropertyName('archive')
        commandLine npm, 'run', '--silent', 'apionly', '--', 'publish', '--target', target, '--channel', 'file'
    }
    buildApiContract
}

def lintApiContracts = tasks.register('lintApiContracts', Exec) {
    group = 'verification'
    description = 'Lints every contract, and fails on a fragment no contract references.'
    dependsOn buildApiContracts
    usesService publisherRuns
    workingDir contracts
    inputs.dir(new File(contracts, 'specs')).withPropertyName('specification')
    inputs.dir(new File(contracts, 'build/dist')).withPropertyName('bundles')
    outputs.dir(new File(contracts, 'build/reports/lint')).withPropertyName('reports')
    commandLine npm, 'run', '--silent', 'apionly', '--', 'lint'
}
tasks.named('check') { dependsOn lintApiContracts }
----

[cols="1,3", options="header"]
|===
|Task |What it does

|`installApiOnlyPublisher`
|`npm ci` in `contracts/`.

|`buildApiContract<Target>`
|Bundles, stamps and lints one contract, from the whole of `contracts/specs/`, because a shared fragment can change any contract.

|`publishApiContract<Target>`
|Packs the contract and writes it to `contracts/build/publish/<target>/<version>/`.

|`lintApiContracts`
|Lints every contract once more, and fails on a YAML file under `contracts/specs/` that no contract references; part of `check`.
|===

.Considerations
* **The tasks are named after the contracts, not after projects**, so any project, calling or implementing, can depend on the one it needs.
* **The shared build service** lets Gradle run in parallel without two Publisher runs sharing `contracts/build/staging/` at once.

[#step-3]
== Step 3: Declare the versions the calling project calls

.storefront/gradle.properties
[source,properties]
----
# The versions of the APIs this project calls.
ordersApiVersion=1.0.0
paymentsApiVersion=1.0.0
----

.Considerations
* **They are the calling project's own decision**, in its own `gradle.properties`, so taking a new version is a change to that project only.
* **Read them with `findProperty`** in the project's build file: `providers.gradleProperty(...)` does not see a subproject's own `gradle.properties`.

== Step 4: Write the contract test first

.storefront/build.gradle
[source,groovy]
----
plugins {
    id 'java'
    id 'com.arc-e-tect.api-only-subscriber'
}

repositories {
    mavenCentral()
}

dependencies {
    testImplementation platform('org.junit:junit-bom:6.1.3')
    testImplementation 'org.junit.jupiter:junit-jupiter'
    testRuntimeOnly 'org.junit.platform:junit-platform-launcher'
}

tasks.named('test') {
    useJUnitPlatform()
    // The versions of the APIs this project calls, for ApiContractTest.
    systemProperty 'ordersApiVersion', findProperty('ordersApiVersion')
    systemProperty 'paymentsApiVersion', findProperty('paymentsApiVersion')
}
----

.storefront/src/test/java/com/example/storefront/ApiContractTest.java
[source,java]
----
package com.example.storefront;

import org.junit.jupiter.api.Test;

import java.io.IOException;
import java.io.InputStream;
import java.nio.charset.StandardCharsets;

import static org.junit.jupiter.api.Assertions.assertNotNull;
import static org.junit.jupiter.api.Assertions.assertTrue;

class ApiContractTest {

    @Test
    void theOrdersApiThisProjectCallsIsOnTheClasspath() throws IOException {
        assertOnTheClasspath("/contracts/orders/openapi.yaml", System.getProperty("ordersApiVersion"));
    }

    @Test
    void thePaymentsApiThisProjectCallsIsOnTheClasspath() throws IOException {
        assertOnTheClasspath("/contracts/payments/openapi.yaml", System.getProperty("paymentsApiVersion"));
    }

    private void assertOnTheClasspath(String path, String version) throws IOException {
        try (InputStream document = getClass().getResourceAsStream(path)) {
            assertNotNull(document, path + " is not on the test classpath");
            String text = new String(document.readAllBytes(), StandardCharsets.UTF_8);
            assertTrue(text.contains("version: " + version), path + " does not declare version " + version);
        }
    }
}
----

Run `./gradlew :storefront:test`, and both tests fail:

[source]
----
ApiContractTest > thePaymentsApiThisProjectCallsIsOnTheClasspath() FAILED
ApiContractTest > theOrdersApiThisProjectCallsIsOnTheClasspath() FAILED
----

[#step-5]
== Step 5: Subscribe to the APIs the project calls

Append to `storefront/build.gradle`:

.storefront/build.gradle (continued)
[source,groovy]
----
apiOnlySubscriber {
    channel {
        type = 'file'
        directory = rootProject.file('contracts/build/publish').path
    }
    // The APIs this project calls, each at the version this project's gradle.properties declares.
    subscribeAsClient('orders') {
        version = findProperty('ordersApiVersion')
    }
    subscribeAsClient('payments') {
        version = findProperty('paymentsApiVersion')
    }
}

// Each fetch reads what the root build publishes.
tasks.named('fetchApiSpecOrders') { dependsOn ':publishApiContractOrders' }
tasks.named('fetchApiSpecPayments') { dependsOn ':publishApiContractPayments' }
----

== Step 7: See the guards fail, once each

=== A change to a shared fragment

Commit everything, then change `BadRequest.yaml` to `description: The request was not valid, and says why.`, and ask the Publisher which contracts that reaches, from `contracts/`:

[source,console]
----
npm run apionly -- changed --since HEAD --quiet
----

[source]
----
orders
payments
----

Run `./gradlew check --continue` without raising any version:

[source]
----
> Task :storefront:fetchApiSpecOrders FAILED
> Task :storefront:fetchApiSpecPayments FAILED
> the published contract for 'orders' 1.0.0 is not the one recorded in apionly.lock:
> the published contract for 'payments' 1.0.0 is not the one recorded in apionly.lock:
----

Raise `version` to `1.0.1` in both `.bundle.properties` files, and both properties in `storefront/gradle.properties` to `1.0.1`, and run `./gradlew check`:

=== A fragment that nothing references

Add `contracts/specs/openapi/components/common/Unused.yaml` without referencing it, and `./gradlew check` fails in `lintApiContracts`, naming the file.

== Step 8: Run it in CI

..github/workflows/build.yml
[source,yaml]
----
name: build

on:
  push:
  pull_request:

permissions:
  contents: read

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v7
      - uses: actions/setup-node@v6
        with:
          node-version: 24
      - uses: actions/setup-java@v5
        with:
          distribution: temurin
          java-version: 21
      - uses: gradle/actions/setup-gradle@v6
      - name: Build, lint and test
        run: ./gradlew check --parallel
      - name: The lockfiles are committed
        run: git diff --exit-code -- '*/apionly.lock'
      - name: Upload the lint reports
        if: always()
        uses: actions/upload-artifact@v7
        with:
          name: api-lint-reports
          path: contracts/build/reports/lint/
----

[#what-you-have]
== What you have now

* One library that owns every fragment, with shared fragments defined once.
* A calling project that builds against a stated version of each API it calls, each verified against its lockfile.
* A build that fails on an unreferenced fragment and on a changed contract under an unchanged version.

[#watch-for]
== What to watch for

* **A project that implements a contract from the library as well** subscribes to that one with `subscribe`, and it lands at the root of its classpath; see link:../../both/implementing-and-calling/tutorial.adoc[the tutorial for implementing one contract and calling others →].
* **A hand edit to `storefront/build/api-spec/` does not survive the next build**; change the fragments instead.
