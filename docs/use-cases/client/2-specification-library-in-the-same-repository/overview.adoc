[#in-short]
== In short

One repository holds a library of API description fragments, and a project that calls APIs described there: a storefront calling `orders` and `payments`, a backend-for-frontend, an end-to-end test suite.
The projects that implement those APIs may live in the same repository too, or not.

The root build runs the API-Only Publisher to build each contract and publish it to a directory in the library's `build/`.
The calling project subscribes to each API it calls as a client, at a version of its own, verifies each against its committed lockfile, and finds each contract on its classpath under `contracts/<target>/`.
Everything happens on the local file system, in one Gradle build.

[#fits]
== When this fits

* The contracts of the APIs your project calls are in a specification library in the same repository.
* Your project calls those APIs; it does not implement them.
* No build outside the repository needs the contracts.

[#does-not-fit]
== When it does not

* **Your project implements a contract from the library.**
That is link:../../provider/2-specification-library-in-the-same-repository/overview.adoc[provider use case 2 →]; if it also calls others, see link:../../both/implementing-and-calling/overview.adoc[implementing one contract and calling others →].
* **The contract lives in your project, and nothing shares it.**
That is link:../1-contract-in-the-calling-project/overview.adoc[client use case 1 →].
* **The library is in another repository.**
That is link:../3-specification-library-in-another-repository/overview.adoc[client use case 3 →] if you can check it out, link:../4-calling-a-published-api/overview.adoc[client use case 4 →] if you only see its releases.

link:../../../README.adoc[The documentation's entry point →] compares every use case.

[#what-you-get]
== What you get

* `./gradlew check` builds, publishes and lints every contract, fails on a fragment no contract references, and runs the calling project's tests against the contracts it calls.
* The calling project's `apionly.lock` records exactly which version of each API it calls.
* A change to a fragment fails the calling project's build until the contract's version is raised and the project takes the new version.
* No registry, no credentials, and nothing generated committed.

[#what-you-do-not-need]
== What you do not need

A registry.
The calling project reads the library's `build/` directory, which gives the Subscriber everything a registry would.

[#adoption]
== Adoption in broad strokes

. **Create the library** in `contracts/`, with a `package.json` that pins the Publisher, the fragments under `contracts/specs/`, a version file per contract, and an `apionly.yaml` with a `file` channel into `contracts/build/`.
. **Build and publish every contract from the root build**: one task per contract that builds it and one that publishes it, and one lint task for the whole library, run one at a time through a shared build service.
. **Declare the version of each API the calling project calls** in its own `gradle.properties`, as `<target>ApiVersion`.
. **Write the contract test first**: it fails until each contract is on the calling project's classpath under `/contracts/<target>/`.
. **Subscribe from the calling project**: the `file` channel on `contracts/build/publish`, a `subscribeAsClient` per API with its own version, and each fetch depending on the root build's publish task for that contract.
. **Commit `apionly.lock`**, and run the same `./gradlew check` in CI.

[#day-to-day]
== Day to day

* **A contract changes**: raise its version in the library, and `<target>ApiVersion` in the calling project, together, and commit the updated `apionly.lock`.
* **A shared fragment changes**: `npm run apionly -- changed --since <ref>`, in `contracts/`, lists the contracts it reaches; raise each one's version, and take each in the calling project.
* **Calling another API**: add its target to the root build's list, a `subscribeAsClient` and a version property in the calling project.
