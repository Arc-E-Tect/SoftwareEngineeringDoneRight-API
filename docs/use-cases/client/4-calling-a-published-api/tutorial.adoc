This tutorial sets up client use case 4 from nothing: a Gradle project, `storefront`, that calls version 1.1.0 of an `orders` API and version 1.0.0 of a `payments` API, whose contracts another team publishes to a Maven repository.
Every file and every command below was run exactly as shown, with API-Only Subscriber 0.2.0, against archives produced by the API-Only Publisher.
Only the repository differs: the run used a Maven repository on disk, which takes no credentials.

It assumes you know how to design an API in OpenAPI and how a Gradle project resolves dependencies.

[#before-you-start]
== Before you start

[cols="1,2", options="header"]
|===
|You need |Version or value

|Java
|21 or newer

|Gradle
|8 or newer, through the project's wrapper

|From the provider
|The Maven repository's URL, the group id, each API's target name, and a released version of each

|Credentials
|A user name and a token that can read the Maven repository
|===

The values used below:

[cols="1,2", options="header"]
|===
|What |Example

|Repository URL
|`https://maven.example.com/repository/contracts`

|Group id
|`com.example.contracts`

|Targets and versions
|`orders` 1.1.0, `payments` 1.0.0
|===

[#step-1]
== Step 1: Declare the version of each API the project calls

.gradle.properties
[source,properties]
----
# The versions of the APIs this project calls.
ordersApiVersion=1.1.0
paymentsApiVersion=1.0.0
----

.Considerations
* **One version per API.**
The providers release on their own schedules, so each API's version changes on its own.
* **Not `apiContractVersion`.**
That property is the version of a contract the project implements, and a client subscription does not read it.

[#step-2]
== Step 2: Write the contract test first

.build.gradle
[source,groovy]
----
plugins {
    id 'java'
}

repositories {
    mavenCentral()
}

dependencies {
    testImplementation platform('org.junit:junit-bom:6.1.3')
    testImplementation 'org.junit.jupiter:junit-jupiter'
    testRuntimeOnly 'org.junit.platform:junit-platform-launcher'
}

tasks.named('test') {
    useJUnitPlatform()
    // The versions of the APIs this project calls, for ApiContractTest.
    systemProperty 'ordersApiVersion', providers.gradleProperty('ordersApiVersion').get()
    systemProperty 'paymentsApiVersion', providers.gradleProperty('paymentsApiVersion').get()
}
----

.src/test/java/com/example/storefront/ApiContractTest.java
[source,java]
----
package com.example.storefront;

import org.junit.jupiter.api.Test;

import java.io.IOException;
import java.io.InputStream;
import java.nio.charset.StandardCharsets;

import static org.junit.jupiter.api.Assertions.assertNotNull;
import static org.junit.jupiter.api.Assertions.assertTrue;

class ApiContractTest {

    @Test
    void theOrdersApiThisProjectCallsIsOnTheClasspath() throws IOException {
        assertOnTheClasspath("orders", System.getProperty("ordersApiVersion"));
    }

    @Test
    void thePaymentsApiThisProjectCallsIsOnTheClasspath() throws IOException {
        assertOnTheClasspath("payments", System.getProperty("paymentsApiVersion"));
    }

    private void assertOnTheClasspath(String target, String version) throws IOException {
        String path = "/contracts/" + target + "/openapi.yaml";
        try (InputStream document = getClass().getResourceAsStream(path)) {
            assertNotNull(document, path + " is not on the test classpath");
            String text = new String(document.readAllBytes(), StandardCharsets.UTF_8);
            assertTrue(text.contains("version: " + version), path + " does not declare version " + version);
        }
    }
}
----

Run `./gradlew test`, and both tests fail:

[source]
----
ApiContractTest > thePaymentsApiThisProjectCallsIsOnTheClasspath() FAILED
ApiContractTest > theOrdersApiThisProjectCallsIsOnTheClasspath() FAILED
----

[#step-3]
== Step 3: Apply the Subscriber

.build.gradle
[source,groovy]
----
plugins {
    id 'java'
    id 'com.arc-e-tect.api-only-subscriber' version '0.2.0'
}

repositories {
    mavenCentral()
    maven {
        name = 'apiContracts'
        url = uri('https://maven.example.com/repository/contracts')
        // Gradle reads apiContractsUsername and apiContractsPassword from
        // gradle.properties outside this project, or from the environment.
        credentials(PasswordCredentials)
    }
}

dependencies {
    testImplementation platform('org.junit:junit-bom:6.1.3')
    testImplementation 'org.junit.jupiter:junit-jupiter'
    testRuntimeOnly 'org.junit.platform:junit-platform-launcher'
}

tasks.named('test') {
    useJUnitPlatform()
    systemProperty 'ordersApiVersion', providers.gradleProperty('ordersApiVersion').get()
    systemProperty 'paymentsApiVersion', providers.gradleProperty('paymentsApiVersion').get()
}

apiOnlySubscriber {
    channel {
        type = 'maven'
        groupId = 'com.example.contracts'
    }
    // The APIs this project calls, each at the version gradle.properties declares.
    subscribeAsClient('orders') {
        version = providers.gradleProperty('ordersApiVersion')
    }
    subscribeAsClient('payments') {
        version = providers.gradleProperty('paymentsApiVersion')
    }
}
----

[cols="1,3", options="header"]
|===
|Setting |What it says

|`repositories { maven { ... } }`
|Where the provider publishes; the `name` decides the credential property names.

|`channel`
|Resolve contracts through Gradle's own dependency resolution, as `com.example.contracts:orders:1.1.0@tgz`.

|`subscribeAsClient('orders')`
|An API this project calls, by its target name, with its own `version`.
An API from another provider sets `groupId` on its subscription, and that provider's repository goes in `repositories`.
|===

[#step-4]
== Step 4: Supply the credentials without committing them

.~/.gradle/gradle.properties
[source,properties]
----
apiContractsUsername=your-user-name
apiContractsPassword=a-token-that-can-read-the-repository
----

In CI, the same two properties as environment variables: `ORG_GRADLE_PROJECT_apiContractsUsername` and `ORG_GRADLE_PROJECT_apiContractsPassword`.

[#step-6]
== Step 6: Commit the lockfile

.apionly.lock
[source]
----
# apionly.lock -- the published contracts this project builds against.
# Generated by the Arc-E-Tect API-Only Subscriber. Commit it; do not edit it.
# Run `verifyApiSpec` to check that what is on disk still matches.
format 1

target orders
version 1.1.0
channel maven
sha256 859cc1e470cc508dbae6ed2c60948a5fc4a65506595918974188f98560075952 openapi.yaml

target payments
version 1.0.0
channel maven
sha256 f36c4659bc427ec6c37ae0d728142cc9dbe7710f676e7f8ec8f999a2ee368626 openapi.yaml
----

One entry per API.
A released version that comes back with different bytes is refused, so the build keeps calling the bundle it locked.

[#step-7]
== Step 7: See the guards fail, once each

Undo each change before the next.

=== A hand-edited fetched document

Append a line to `build/api-spec/payments/openapi.yaml`, and run `./gradlew verifyApiSpec` on its own:

[source]
----
> the contract for 'payments' has drifted from apionly.lock:
    - openapi.yaml has changed since it was locked
        locked:  f36c4659bc427ec6c37ae0d728142cc9dbe7710f676e7f8ec8f999a2ee368626
        on disk: d3a2cb4c565b7261933af97412292ded21434ae36d2ad364107a0df134931aee
----

`./gradlew fetchApiSpec` restores it.

=== A pre-release, without asking for one

Set `ordersApiVersion=1.1.0-rc.1`, and run `./gradlew fetchApiSpec`:

[source]
----
> subscription 'orders' resolves the pre-release version 1.1.0-rc.1.
  A contract that is not finished must not quietly satisfy a build. Set allowPrerelease = true on this subscription to work against it deliberately, and remember to take it off again before release.
----

To work against it deliberately, add `allowPrerelease = true` to that subscription only:

[source,groovy]
----
    subscribeAsClient('orders') {
        version = providers.gradleProperty('ordersApiVersion')
        allowPrerelease = true
    }
----

[source]
----
Updated orders from 1.1.0 to 1.1.0-rc.1
----

[#step-8]
== Step 8: Run it in CI

..github/workflows/build.yml
[source,yaml]
----
name: build

on:
  push:
  pull_request:

permissions:
  contents: read

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v7
      - uses: actions/setup-java@v5
        with:
          distribution: temurin
          java-version: 21
      - uses: gradle/actions/setup-gradle@v6
      - name: Fetch, verify and test
        env:
          ORG_GRADLE_PROJECT_apiContractsUsername: ${{ secrets.API_CONTRACTS_USERNAME }}
          ORG_GRADLE_PROJECT_apiContractsPassword: ${{ secrets.API_CONTRACTS_TOKEN }}
        run: ./gradlew check
      - name: The lockfile is committed
        run: git diff --exit-code -- apionly.lock
----

[#step-9]
== Step 9: Take a new version of one API

When the provider releases `orders` 1.2.0, change `ordersApiVersion=1.2.0` and run `./gradlew check`.
It prints `Updated orders from 1.1.0 to 1.2.0`, and only the `orders` entry in `apionly.lock` changes.
Commit both files together.

[#what-you-have]
== What you have now

* A build that calls a stated version of each API, verified on every `check`.
* A committed record of exactly which versions those are.
* A test that proves each contract reaches the code.

[#watch-for]
== What to watch for

* **Generate clients from the fetched documents, not from copies**: wire a generator to `apiOnlySubscriber.subscription('orders').openapi`, which carries the dependency on the fetch.
* **An API published somewhere else**, such as a directory or another provider's repository, gets a `channel { }` of its own inside its `subscribeAsClient` block; every setting it leaves out comes from the project's channel.
* **Publishing is passive.**
Nothing tells your project a new version exists; watch the providers' releases, or teach an update bot to read the version properties.
