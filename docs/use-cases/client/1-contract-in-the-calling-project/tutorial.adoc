This tutorial builds client use case 1 from nothing: one Gradle project, `storefront`, that calls an `orders` API, holds that API's OpenAPI description, and builds against a versioned, verified copy of it.
Every file and every command below was run exactly as shown, with API-Only Publisher 0.3.0 and API-Only Subscriber 0.2.0.

It assumes you know how to design an API in OpenAPI, how a bundler such as https://redocly.com/docs/cli/[Redocly CLI ↗] resolves `$ref`s into one document, and how a Gradle project is laid out.

[#before-you-start]
== Before you start

[cols="1,2", options="header"]
|===
|You need |Version

|Node.js and npm
|Node.js `^22.14.0`, `^24.10.0` or `>=26.0.0`

|Java
|21 or newer

|Gradle
|8 or newer, through the project's wrapper

|A Gradle project
|With the `java` plugin applied, called `storefront` below
|===

The API is called `orders` throughout.
In the Publisher's terms that name is the *target*: it names the contract, its archive, its lockfile entry, the Gradle tasks that handle it, and its directory on the classpath.

[#what-you-build]
== What you will build

[source]
----
storefront/
├── package.json                    Pins the API-Only Publisher
├── package-lock.json
├── apionly.yaml                    What the Publisher builds, and where it puts it
├── .redocly.yaml                   The lint rules
├── gradle.properties               ordersApiVersion: the version of the orders API this project calls
├── build.gradle                    Builds, publishes, lints and fetches the contract
├── apionly.lock                    Generated by the build, committed
└── src/
    ├── main/api/openapi/
    │   ├── bundles/orders.yaml     The bundle root
    │   ├── bundles/orders.bundle.properties   The contract's version
    │   ├── paths/Orders.yaml
    │   └── components/schemas/OrderList.yaml
    └── test/java/com/example/storefront/ApiContractTest.java
----

[#step-1]
== Step 1: Pin the Publisher

.package.json
[source,json]
----
{
  "name": "storefront-api",
  "private": true,
  "scripts": {
    "apionly": "api-only-publisher"
  }
}
----

[source,console]
----
npm install --save-dev --save-exact @arc-e-tect/api-only-publisher@0.3.0
----

Add `node_modules/` and `build/` to `.gitignore`, and commit `package.json` and `package-lock.json`.

.Considerations
* **Run the Publisher only through the script**: `npm run apionly -- <command>`.
`npx api-only-publisher` is not this package; npx would look that unscoped name up on the public registry.

[#step-2]
== Step 2: Write the fragments

.src/main/api/openapi/bundles/orders.yaml
[source,yaml]
----
openapi: 3.1.1
info:
  title: Orders API
  version: 0.0.0
  license:
    name: MIT
    identifier: MIT
servers:
  - url: https://api.orders.test
security: []
paths:
  /orders:
    $ref: ../paths/Orders.yaml
----

.src/main/api/openapi/paths/Orders.yaml
[source,yaml]
----
get:
  operationId: listOrders
  summary: List the orders.
  responses:
    '200':
      description: The orders.
      content:
        application/json:
          schema:
            $ref: ../components/schemas/OrderList.yaml
    '400':
      description: The request was not valid.
----

.src/main/api/openapi/components/schemas/OrderList.yaml
[source,yaml]
----
type: array
items:
  type: string
----

.Considerations
* **Describe what the project calls.**
A consumer-defined contract holds the operations and fields this project relies on; that is what makes it a useful contract to hand to the provider.
* **`info.version` is a placeholder**: the build overwrites it with the contract's version, so `0.0.0` is conventional, and it has to be present.

== Step 3: Choose the lint rules

.`.redocly.yaml`, at the project root

  - recommended

== Step 4: Give the contract a version

.src/main/api/openapi/bundles/orders.bundle.properties
[source,properties]
----
# The version of the orders contract. Major for a breaking change, minor for an
# additive one, patch for anything else. Change it with the fragments it describes.

----

[#step-5]
== Step 5: Describe the build in `apionly.yaml`

.apionly.yaml
[source,yaml]
----
schemaVersion: 1

sources:
  root: src/main/api
  openapi: openapi

defaults:
  openapi:
    lint: .redocly.yaml
    outputName: openapi.yaml

build:
  staging: build/api-only/staging
  dist: build/api-only/dist

reports:
  lint: build/api-only/reports/lint

toolchain:
  redocly: "@redocly/cli@2.52.0"

channels:
  file:
    directory: build/api-only/publish
    clean: true

targets:
  orders:
    openapi:
      bundle: bundles/orders.yaml
----

[cols="1,3", options="header"]
|===
|Key |What it says

|`sources.root`, `sources.openapi`
|The fragments are under `src/main/api/openapi/`; a bundle path is relative to that directory.

|`defaults.openapi`
|The lint rules, and the bundled document's name; keep `openapi.yaml`, because the Subscriber looks for exactly that name.

|`build`, `reports`
|Everything the Publisher writes goes under `build/api-only/`.

|`toolchain.redocly`
|The exact Redocly CLI version the Publisher runs.

|`channels.file`
|Publishing writes a versioned archive to `build/api-only/publish/`; `clean: true` keeps only the version published last.
|===

Try it:

[source,console]
----
npm run apionly -- build
npm run apionly -- lint
----

[source]
----
Built 1 document(s).
Linted 1 document(s).
----

[#step-6]
== Step 6: Declare the version the project calls

.gradle.properties
[source,properties]
----
# The version of the orders API this project calls.
ordersApiVersion=1.0.0
----

.Considerations
* **The name is yours to choose.**
The Subscriber reads a client subscription's version from the build file; this tutorial keeps it in `gradle.properties`, as `<target>ApiVersion`, so the version is one reviewable line.
* **It is not `apiContractVersion`.**
That property is the version of a contract the project implements, and a client subscription does not read it.

== Step 7: Write the contract test first

.build.gradle
[source,groovy]
----
plugins {
    id 'java'
    id 'com.arc-e-tect.api-only-subscriber' version '0.2.0'
}

repositories {
    mavenCentral()
}

dependencies {
    testImplementation platform('org.junit:junit-bom:6.1.3')
    testImplementation 'org.junit.jupiter:junit-jupiter'
    testRuntimeOnly 'org.junit.platform:junit-platform-launcher'
}

tasks.named('test') {
    useJUnitPlatform()
    // The version of the orders API this project calls, for ApiContractTest.
    systemProperty 'ordersApiVersion', providers.gradleProperty('ordersApiVersion').get()
}
----

.src/test/java/com/example/storefront/ApiContractTest.java
[source,java]
----
package com.example.storefront;

import org.junit.jupiter.api.Test;

import java.io.IOException;
import java.io.InputStream;
import java.nio.charset.StandardCharsets;

import static org.junit.jupiter.api.Assertions.assertNotNull;
import static org.junit.jupiter.api.Assertions.assertTrue;

class ApiContractTest {

    @Test
    void theOrdersApiThisProjectCallsIsOnTheClasspath() throws IOException {
        try (InputStream document = getClass().getResourceAsStream("/contracts/orders/openapi.yaml")) {
            assertNotNull(document, "contracts/orders/openapi.yaml is not on the test classpath");
            String text = new String(document.readAllBytes(), StandardCharsets.UTF_8);
            String version = System.getProperty("ordersApiVersion");
            assertTrue(text.contains("version: " + version),
                "contracts/orders/openapi.yaml does not declare version " + version);
        }
    }
}
----

[source,console]
----
./gradlew test
----

[source]
----
ApiContractTest > theOrdersApiThisProjectCallsIsOnTheClasspath() FAILED
    org.opentest4j.AssertionFailedError at ApiContractTest.java:17
----

.Considerations
* **The path is `/contracts/orders/`, not the classpath root.**
The root is reserved for a contract the project implements; every API it calls has a directory of its own, so any number of them fit side by side.

[#step-8]
== Step 8: Wire the contract into the build

Append to `build.gradle`:

.build.gradle (continued)
[source,groovy]
----
// ---------------------------------------------------------------------------
// The contract of the orders API this project calls. The Publisher builds and
// publishes it to a directory in build/, and the Subscriber fetches it from
// there as a client subscription, verifies it against apionly.lock, and puts it
// on the classpath under contracts/orders/.
// ---------------------------------------------------------------------------

def npm = System.getProperty('os.name').toLowerCase().contains('windows') ? 'npm.cmd' : 'npm'

def installApiOnlyPublisher = tasks.register('installApiOnlyPublisher', Exec) {
    group = 'api-only'
    description = 'Installs the API-Only Publisher at the version package-lock.json pins.'
    inputs.files('package.json', 'package-lock.json').withPropertyName('manifests')
    outputs.file('node_modules/.package-lock.json').withPropertyName('installation')
    commandLine npm, 'ci', '--no-audit', '--no-fund'
}

def buildApiContract = tasks.register('buildApiContract', Exec) {
    group = 'api-only'
    description = 'Bundles, stamps and lints the orders contract.'
    dependsOn installApiOnlyPublisher
    inputs.dir('src/main/api').withPropertyName('specification')
    inputs.files('apionly.yaml', 'package-lock.json').withPropertyName('configuration')
    outputs.dir('build/api-only/dist/orders').withPropertyName('bundle')
    commandLine npm, 'run', '--silent', 'apionly', '--', 'build', '--target', 'orders'
}

def publishApiContract = tasks.register('publishApiContract', Exec) {
    group = 'api-only'
    description = 'Publishes the orders contract to the file channel in build/api-only/publish.'
    dependsOn buildApiContract
    inputs.dir('build/api-only/dist/orders').withPropertyName('bundle')
    outputs.dir('build/api-only/publish/orders').withPropertyName('archive')
    commandLine npm, 'run', '--silent', 'apionly', '--', 'publish', '--target', 'orders', '--channel', 'file'
}

def lintApiContract = tasks.register('lintApiContract', Exec) {
    group = 'verification'
    description = 'Lints the contract, and fails on a fragment nothing references.'
    dependsOn buildApiContract
    inputs.dir('src/main/api').withPropertyName('specification')
    inputs.dir('build/api-only/dist').withPropertyName('bundles')
    outputs.dir('build/api-only/reports/lint').withPropertyName('reports')
    commandLine npm, 'run', '--silent', 'apionly', '--', 'lint'
}
tasks.named('check') { dependsOn lintApiContract }

apiOnlySubscriber {
    channel {
        type = 'file'
        directory = file('build/api-only/publish').path
    }
    // An API this project calls, at the version gradle.properties declares.
    subscribeAsClient('orders') {
        version = providers.gradleProperty('ordersApiVersion')
    }
}

// The fetch reads what publishApiContract writes.
tasks.named('fetchApiSpecOrders') { dependsOn publishApiContract }
----

[cols="1,3", options="header"]
|===
|Task |What it does

|`installApiOnlyPublisher`
|`npm ci`, so the build runs exactly the Publisher `package-lock.json` pins.

|`buildApiContract`
|Bundles the fragments, stamps the version from `orders.bundle.properties`, and lints the result.

|`publishApiContract`
|Packs the bundled document with a `manifest.json` of its hashes, and writes it to `build/api-only/publish/orders/<version>/`.

|`lintApiContract`
|Lints again, and fails on a YAML file under `src/main/api/` that the contract does not reference; part of `check`.

|`fetchApiSpecOrders`, from the Subscriber
|Reads the archive at `ordersApiVersion`, checks every document against its manifest, unpacks it into `build/api-spec/orders/`, records it in `apionly.lock`, and makes `processResources` copy it to `contracts/orders/`.

|`verifyApiSpecOrders`, from the Subscriber
|Checks the documents on disk against `apionly.lock`; part of `check`.
|===

[#step-10]
== Step 10: See the guards fail, once each

Undo each change before the next, except where a section builds on the one before.

=== A fragment that changed under an unchanged version

Change `summary: List the orders.` in `Orders.yaml` to `summary: List every order.`, change no version, and run `./gradlew check`:

[source]
----
> Task :fetchApiSpecOrders FAILED
> the published contract for 'orders' 1.0.0 is not the one recorded in apionly.lock:
  1.0.0 was published to the file channel again, with different content. Find out why before accepting this: if the change was intended, publish it as a new version and subscribe to that; if it was not, publish the specifications the locked contract came from again. Delete the entry from apionly.lock only to re-lock deliberately.
----

Between those two lines, the message lists each document that differs, with its locked and its published hash.

=== The change done properly

Keep the changed summary, raise `version` in `orders.bundle.properties` to `1.1.0` and `ordersApiVersion` in `gradle.properties` to `1.1.0`, and run `./gradlew check`:

[source]
----
Updated orders from 1.0.0 to 1.1.0
BUILD SUCCESSFUL
----

=== Only one of the two versions raised

Raise only `ordersApiVersion`, to `1.2.0`:

[source]
----
> no archive for 'orders' 1.2.0 at .../build/api-only/publish/orders/1.2.0/orders-1.2.0.tgz.
  Published versions of 'orders': 1.1.0.
  Publish 1.2.0 first, or subscribe to a version that is published.
----

=== A client subscription without a version

Remove the `version` line from `subscribeAsClient('orders')`, and run `./gradlew fetchApiSpec`:

[source]
----
> client subscription 'orders' declares no version. Set version on the subscription: an API this project calls sets its own, because apiOnlySubscriber.version and the apiContractVersion project property are the version of the contract this project implements.
----

=== The same contract implemented and called

Add `subscribe('orders')` above `subscribeAsClient('orders')`:

[source]
----
> apiOnlySubscriber implements 'orders', so it cannot also subscribe to it as a client. A project either implements a contract or calls it.
----

== Step 11: Run it in CI

..github/workflows/build.yml
[source,yaml]
----
name: build

on:
  push:
  pull_request:

permissions:
  contents: read

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v7
      - uses: actions/setup-node@v6
        with:
          node-version: 24
      - uses: actions/setup-java@v5
        with:
          distribution: temurin
          java-version: 21
      - uses: gradle/actions/setup-gradle@v6
      - name: Build, lint and test
        run: ./gradlew check
      - name: The lockfile is committed
        run: git diff --exit-code -- apionly.lock
      - name: Upload the lint reports
        if: always()
        uses: actions/upload-artifact@v7
        with:
          name: api-lint-reports
          path: build/api-only/reports/lint/
----

[#what-you-have]
== What you have now

* The contract of the API this project calls, built from fragments, linted, and published as a versioned archive on every build.
* A committed lockfile that says exactly which version of that contract the project calls.
* A build that fails on an unreferenced fragment, on a changed contract under an unchanged version, and on versions that disagree.
* A test that proves the contract reaches the code.

[#watch-for]
== What to watch for

* **The provider is not bound by this contract** until it builds against it.
Hand the provider the bundled document, or move the contract to a library both sides subscribe to.
* **More APIs** mean more `subscribeAsClient` blocks, each with its own version, and each on the classpath under its own directory.
* **A hand edit to `build/api-spec/orders/openapi.yaml` does not survive the next build**; change the fragments instead.
