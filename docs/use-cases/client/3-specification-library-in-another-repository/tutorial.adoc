This tutorial sets up client use case 3 from nothing: a Gradle project, `storefront`, in its own repository, that calls the `orders` API released by a `contracts` repository you can check out.
The `contracts` repository is the one link:../../provider/3-specification-library-in-its-own-repository/tutorial.adoc[provider use case 3's tutorial →] builds; this tutorial uses it as that tutorial leaves it, with `orders` 1.1.0 released and a `file` channel added in its step 13.

Every file and every command below was run exactly as shown, with API-Only Subscriber {api-only-subscriber-version} and API-Only Publisher {api-only-publisher-version}.
Those are the versions it was verified with; a newer release works the same unless its changelog says otherwise, and the README of link:../../../../api-only-publisher/README.adoc[the Publisher →] and link:../../../../api-only-subscriber/README.adoc[the Subscriber →] says which release is the latest.
Only the repository differs: the run used the `contracts` repository's Maven repository on disk, which takes no credentials.

[#before-you-start]
== Before you start

[cols="1,2", options="header"]
|===
|You need |Version or value

|Java and Gradle
|Java 21 or newer, Gradle 8 or newer

|Node.js and npm
|Only to publish a pre-release from your checkout of `contracts`

|From the library
|The Maven repository's URL, the group id, and the target name of each API

|A checkout
|Of the `contracts` repository, beside `storefront`, when you work ahead of a release
|===

[source]
----
workspace/
├── contracts/     A checkout of the specification library
└── storefront/    This project
----

[#step-1]
== Step 1: Declare the version of the API the project calls

.gradle.properties
[source,properties]
----
# The version of the orders API this project calls.
ordersApiVersion=1.1.0
----

[#step-2]
== Step 2: Write the contract test first

.src/test/java/com/example/storefront/ApiContractTest.java
[source,java]
----
package com.example.storefront;

import org.junit.jupiter.api.Test;

import java.io.IOException;
import java.io.InputStream;
import java.nio.charset.StandardCharsets;

import static org.junit.jupiter.api.Assertions.assertNotNull;
import static org.junit.jupiter.api.Assertions.assertTrue;

class ApiContractTest {

    @Test
    void theOrdersApiThisProjectCallsIsOnTheClasspath() throws IOException {
        try (InputStream document = getClass().getResourceAsStream("/contracts/orders/openapi.yaml")) {
            assertNotNull(document, "contracts/orders/openapi.yaml is not on the test classpath");
            String text = new String(document.readAllBytes(), StandardCharsets.UTF_8);
            String version = System.getProperty("ordersApiVersion");
            assertTrue(text.contains("version: " + version),
                "contracts/orders/openapi.yaml does not declare version " + version);
        }
    }
}
----

Until step 3 wires the Subscriber, `./gradlew test` fails: `contracts/orders/openapi.yaml is not on the test classpath`.

[#step-3]
== Step 3: Subscribe to the released contract

.build.gradle
[source,groovy,subs="attributes+"]
----
plugins {
    id 'java'
    id 'com.arc-e-tect.api-only-subscriber' version '{api-only-subscriber-version}'
}

repositories {
    mavenCentral()
    maven {
        name = 'apiContracts'
        url = uri('https://maven.example.com/repository/contracts')
        // Gradle reads apiContractsUsername and apiContractsPassword from
        // gradle.properties outside this project, or from the environment.
        credentials(PasswordCredentials)
    }
}

dependencies {
    testImplementation platform('org.junit:junit-bom:6.1.3')
    testImplementation 'org.junit.jupiter:junit-jupiter'
    testRuntimeOnly 'org.junit.platform:junit-platform-launcher'
}

tasks.named('test') {
    useJUnitPlatform()
    // The version of the orders API this project calls, for ApiContractTest.
    systemProperty 'ordersApiVersion', providers.gradleProperty('ordersApiVersion').get()
}

apiOnlySubscriber {
    channel {
        type = 'maven'
        groupId = 'com.example.contracts'
    }
    // The orders API this project calls, at the version gradle.properties declares.
    subscribeAsClient('orders') {
        version = providers.gradleProperty('ordersApiVersion')
    }
}
----

Put `apiContractsUsername` and `apiContractsPassword` in `~/.gradle/gradle.properties`, and run `./gradlew check`:

[source]
----
> Task :fetchApiSpecOrders
Subscribed to orders 1.1.0
> Task :test
> Task :verifyApiSpecOrders
> Task :verifyApiSpec

BUILD SUCCESSFUL
----

[#step-4]
== Step 4: Commit the lockfile

.apionly.lock
[source]
----
# apionly.lock -- the published contracts this project builds against.
# Generated by the Arc-E-Tect API-Only Subscriber. Commit it; do not edit it.
# Run `verifyApiSpec` to check that what is on disk still matches.
format 1

target orders
version 1.1.0
channel maven
sha256 ab7b2899eed2ec77158f50da8775f0264f8048c03e014cffe1bd1c9a292eeb01 openapi.yaml
----

In CI, the credentials come from `ORG_GRADLE_PROJECT_apiContractsUsername` and `ORG_GRADLE_PROJECT_apiContractsPassword`, and a step fails the build when `git diff --exit-code -- apionly.lock` shows a change, as in link:../4-calling-a-published-api/tutorial.adoc#step-8[client use case 4's tutorial →].

[#step-5]
== Step 5: Propose a contract change

When `storefront` needs something `orders` does not offer yet, change the contract where it lives: in `contracts`, in a pull request that raises the contract's version, for example to `1.2.0`.
That repository's pull-request checks lint the change and fail when the version was not raised.

[#step-6]
== Step 6: Work against the change before it is released

In your checkout of `contracts`, with the change in place, publish a pre-release to its `file` channel:

[source,console]
----
cd ../contracts
npm ci
npm run apionly -- build --target orders --pre-release rc.1
npm run apionly -- publish --target orders --pre-release rc.1 --channel file
----

That writes `contracts/build/publish/orders/<version>-rc.1/`.

In `storefront`, subscribe to that pre-release from the checkout: set `ordersApiVersion` to the pre-release version, give that subscription a `channel { }` of its own on the directory, and allow the pre-release on it.
With `1.1.0` in the version file when this was run, that is `1.1.0-rc.1`:

.gradle.properties (while working ahead)
[source,properties]
----
ordersApiVersion=1.1.0-rc.1
----

.build.gradle (while working ahead)
[source,groovy]
----
apiOnlySubscriber {
    channel {
        type = 'maven'
        groupId = 'com.example.contracts'
    }
    // The orders API this project calls, at the version gradle.properties declares.
    subscribeAsClient('orders') {
        version = providers.gradleProperty('ordersApiVersion')
        // Deliberate and temporary: remove at the release.
        allowPrerelease = true
        channel {
            type = 'file'
            directory = '../contracts/build/publish'
        }
    }
}
----

[source]
----
Updated orders from 1.1.0 to 1.1.0-rc.1
BUILD SUCCESSFUL
----

`apionly.lock` now records where the contract came from:

[source]
----
target orders
version 1.1.0-rc.1
channel file
sha256 f5b49f2a2013de11b86cb9da3430f955e68d4db78879ab8282ff2e86c1b8cc5a openapi.yaml
----

.Considerations
* **Do not push this.**
CI has neither your checkout nor your pre-release.
* **Only this subscription reads the checkout.**
Every other API `storefront` calls keeps resolving through the project's `maven` channel.

[#step-7]
== Step 7: Take the release

Once `contracts` releases the change, remove the subscription's own `channel { }` and `allowPrerelease`, set `ordersApiVersion` to the released version, run `./gradlew check`, and commit `build.gradle`, `gradle.properties` and `apionly.lock` together.

[#what-you-have]
== What you have now

* A project that calls a released, verified version of the API.
* A way to try a contract change before its release, visibly and temporarily.
* Contract changes proposed and reviewed in the specification library.

[#watch-for]
== What to watch for

* **A lockfile with `channel file` must never reach the main branch.**
The lockfile check in CI catches a build that could not resolve it; review catches the rest.
* **A pre-release version in `gradle.properties`** is the other sign someone forgot to switch back.
