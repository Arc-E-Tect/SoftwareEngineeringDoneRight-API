This tutorial builds a repository, `shop`, with a library of API description fragments for three APIs, `billing`, `orders` and `payments`, and a project, `billing`, that implements the `billing` API and calls the other two.
Every file and every command below was run exactly as shown, with API-Only Publisher {api-only-publisher-version} and API-Only Subscriber {api-only-subscriber-version}.

It assumes you know how to design an API in OpenAPI and how a multi-project Gradle build is laid out.

== Step 1: The library

Create `contracts/` exactly as link:../../client/2-specification-library-in-the-same-repository/tutorial.adoc#step-1[step 1 of client use case 2's tutorial →] does, with a third contract, `billing`, beside `orders` and `payments`:

.contracts/specs/openapi/bundles/billing.yaml
[source,yaml]
----
openapi: 3.1.1
info:
  title: Billing API
  version: 0.0.0
  license:
    name: MIT
    identifier: MIT
servers:
  - url: https://api.billing.test
security: []
paths:
  /billing:
    $ref: ../paths/Billing.yaml
----

.contracts/specs/openapi/paths/Billing.yaml
[source,yaml]
----
get:
  operationId: listBilling
  summary: List the billing.
  responses:
    '200':
      description: The billing.
      content:
        application/json:
          schema:
            type: array
            items:
              type: string
    '400':
      $ref: ../components/common/BadRequest.yaml
----

.contracts/specs/openapi/bundles/billing.bundle.properties
[source,properties]
----
# The version of the billing contract.
version=1.0.0
----

and a third target in `contracts/apionly.yaml`:

[source,yaml]
----
targets:
  billing:
    openapi:
      bundle: bundles/billing.yaml
  orders:
    openapi:
      bundle: bundles/orders.yaml
  payments:
    openapi:
      bundle: bundles/payments.yaml
----

The root `build.gradle` is link:../../client/2-specification-library-in-the-same-repository/tutorial.adoc#step-2[the one from client use case 2 →], with all three contracts in its list:

[#step-3]
== Step 3: Declare the versions

.billing/gradle.properties
[source,properties]
----
# The version of the billing contract this project implements.
apiContractVersion=1.0.0

# The versions of the APIs this project calls.
ordersApiVersion=1.0.0
paymentsApiVersion=1.0.0
----

.Considerations
* **Two kinds of version.**
`apiContractVersion` is the contract the project implements, and the Subscriber reads it for `subscribe`.
Each `<target>ApiVersion` is an API it calls, which the build file passes to `subscribeAsClient` itself.

[#step-4]
== Step 4: Write the contract test first

.billing/src/test/java/com/example/billing/ApiContractTest.java
[source,java]
----
package com.example.billing;

import org.junit.jupiter.api.Test;

import java.io.IOException;
import java.io.InputStream;
import java.nio.charset.StandardCharsets;

import static org.junit.jupiter.api.Assertions.assertNotNull;
import static org.junit.jupiter.api.Assertions.assertTrue;

class ApiContractTest {

    @Test
    void theContractThisProjectImplementsIsAtTheRootOfTheClasspath() throws IOException {
        assertOnTheClasspath("/openapi.yaml", System.getProperty("apiContractVersion"));
    }

    @Test
    void theOrdersApiThisProjectCallsIsOnTheClasspath() throws IOException {
        assertOnTheClasspath("/contracts/orders/openapi.yaml", System.getProperty("ordersApiVersion"));
    }

    @Test
    void thePaymentsApiThisProjectCallsIsOnTheClasspath() throws IOException {
        assertOnTheClasspath("/contracts/payments/openapi.yaml", System.getProperty("paymentsApiVersion"));
    }

    private void assertOnTheClasspath(String path, String version) throws IOException {
        try (InputStream document = getClass().getResourceAsStream(path)) {
            assertNotNull(document, path + " is not on the test classpath");
            String text = new String(document.readAllBytes(), StandardCharsets.UTF_8);
            assertTrue(text.contains("version: " + version), path + " does not declare version " + version);
        }
    }
}
----

[#step-5]
== Step 5: Subscribe to all three

.billing/build.gradle
[source,groovy]
----
plugins {
    id 'java'
    id 'com.arc-e-tect.api-only-subscriber'
}

repositories {
    mavenCentral()
}

dependencies {
    testImplementation platform('org.junit:junit-bom:6.1.3')
    testImplementation 'org.junit.jupiter:junit-jupiter'
    testRuntimeOnly 'org.junit.platform:junit-platform-launcher'
}

tasks.named('test') {
    useJUnitPlatform()
    // The contract this project implements, and the APIs it calls, for ApiContractTest.
    systemProperty 'apiContractVersion', findProperty('apiContractVersion')
    systemProperty 'ordersApiVersion', findProperty('ordersApiVersion')
    systemProperty 'paymentsApiVersion', findProperty('paymentsApiVersion')
}

apiOnlySubscriber {
    channel {
        type = 'file'
        directory = rootProject.file('contracts/build/publish').path
    }

    // The contract this project implements, at apiContractVersion.
    subscribe('billing')

    // The APIs it calls, each at its own version.
    subscribeAsClient('orders') {
        version = findProperty('ordersApiVersion')
    }
    subscribeAsClient('payments') {
        version = findProperty('paymentsApiVersion')
    }
}

// Each fetch reads what the root build publishes.
tasks.named('fetchApiSpecBilling') { dependsOn ':publishApiContractBilling' }
tasks.named('fetchApiSpecOrders') { dependsOn ':publishApiContractOrders' }
tasks.named('fetchApiSpecPayments') { dependsOn ':publishApiContractPayments' }
----

[#step-7]
== Step 7: See how the roles differ

=== The implemented contract changes on its own

Change `summary: List the billing.` in `Billing.yaml` to `summary: List every invoice.`, raise `version` in `billing.bundle.properties` and `apiContractVersion` to `1.1.0`, and run `./gradlew check`:

[source]
----
Updated billing from 1.0.0 to 1.1.0
BUILD SUCCESSFUL
----

`orders` and `payments` stay at `1.0.0`.

=== A called API declared as implemented

Change `subscribeAsClient('orders') {` to `subscribe('orders') {`, and run any task:

[source]
----
> apiOnlySubscriber already implements 'billing', so it cannot also implement 'orders'.
  A project implements one API contract: two in one project would share one version, one classpath root and one release, so neither could change without the other.
  If this project calls 'orders' rather than implementing it, declare it with subscribeAsClient('orders') instead.
  If it implements both, put each contract in a project of its own, in a multi-project build, with its own apiOnlySubscriber block and apiContractVersion.
  See https://github.com/Arc-E-Tect/SoftwareEngineeringDoneRight-API/blob/main/api-only-subscriber/README.adoc#one-contract-per-project
----

Put `subscribeAsClient` back.

[#watch-for]
== What to watch for

* **Contracts from elsewhere.**
Every subscription in `billing` resolves through the project's `file` channel here; an API published to a Maven repository gets a `channel { }` of its own inside its `subscribeAsClient` block, as link:overview.adoc#combining[the overview →] shows.
* **A server framework that serves `/openapi.yaml`** serves the implemented contract only; the called APIs stay under `/contracts/`.
