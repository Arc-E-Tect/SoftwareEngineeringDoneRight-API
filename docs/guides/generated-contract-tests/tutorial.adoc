This tutorial adopts generated contract tests in a small Spring Boot service, a catalogue of books, step by step.
Every listing is included from link:{example-dir}/README.adoc[the generated contract tests example →], and every command was run in it, with API-Only TranscriberJ {api-only-transcriberj-version}, its REST Docs emitter {api-only-transcriberj-restdocs-version}, its WireMock emitter {api-only-transcriberj-wiremock-version} and API-Only Publisher {api-only-publisher-version}.
The example is built in CI.

link:overview.adoc[The overview →] makes the argument this tutorial puts into practice.

[WARNING]
.Generated stateless contract tests are not independent of each other
====
A stateless case the service wrongly accepts leaves state behind, and later cases then answer differently.
Read the first failing stateless test first, fix it, and re-run on fresh state before you diagnose the next: link:overview.adoc#testing-principle[The testing principle →].
====

Its first lines, from a run of the example:

[source,text]
----
API-Only TranscriberJ: books 1.0.1
0 degraded method(s), 0 recommendation(s), 0 undecided construct(s), 0 warning(s), 0 method(s) without a valid value, 0 parameter(s) not supported yet
Invalid requests: 30 case(s) derived, 26 constraint(s) covered, 3 uncovered (not isolatable: 1, changes the route: 1, not expressible in a parameter: 1), 0 gap(s)
Contract cases: 5 success, 1 not found, 1 not acceptable, 1 unsupported media type, 30 invalid request; 1 declared response(s) not covered (depends on behaviour or state the contract does not describe: 1)
----

Nothing is degraded, nothing is recommended, and there is no gap: every operation that constrains its input declares `400`.
Three constraints have no case, each for a reason no contract can avoid: a path parameter's `required` changes the route, its `type` cannot be broken since every parameter travels as a string, and every value that breaks the `type` of the `format` enum breaks the enum too.

Its response coverage lists 38 cases, and one response with none:

[source,text]
----
  CreateBookContractCases 409: uncovered, depends on behaviour or state the contract does not describe -- the contract does not say what provokes 409
----

That `409` is the one contract test you write by hand, in <<hand-written,Step 7 §>>.

== Step 3: The shared interfaces, and one leaf per target

For each operation, the REST Docs emitter generates `<Operation>ContractTests` in `com.example.books.contract.restdocs`: `CreateBookContractTests`, `GetBookContractTests` and `ListBooksContractTests`.
This is the start of `GetBookContractTests`, as generated:

[source,java]
----
public interface GetBookContractTests {

    WebTestClient client();

    default void arrangeState(ContractCase contractCase) {
        throw new FixtureNotImplementedException(contractCase, "GetBookContractTests", "@Override\npublic void arrangeState(ContractCase contractCase) {\n    switch (contractCase.id()) { ...");
    }

    default void arrangeStatelessCase(ContractCase contractCase) {
    }

    default String generatedDocumentationPrefix() {
        return ContractTestSupport.DEFAULT_PREFIX;
    }

    @Test
    @DisplayName("GET /books/{id}: a valid request with the required parameters and body members only returns 200")
    default void success200Required_returns200() {
        ContractCase contractCase = GetBookContractCases.CASES.get(0);
        arrangeState(contractCase);
        ContractTestSupport.clientFor(client(), contractCase).get()
                .uri(GetBookOperation.PATH, ContractTestSupport.pathValues(contractCase))
                // ... the case's headers, then the status, the content type, and document()
    }
    // ... notFound_returns404, notAcceptable_returns406, pathIdPattern_returns400
}
----

The Javadoc is left out, and the elided parts are marked `...`; the file is `build/generated/sources/transcriberj/books/restdocs/com/example/books/contract/restdocs/GetBookContractTests.java`.
