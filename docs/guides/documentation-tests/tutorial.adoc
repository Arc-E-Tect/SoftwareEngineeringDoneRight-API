[#descriptors]
== Step 3: Request fields, response fields and path parameters

The test above already documents its fields with the generated descriptors: `BookRequestV1Docs.requestFields()` and `BookV1Docs.responseFields()`.
Each is a snippet, and a check: a request or response whose fields do not match the contract -- a member missing, an undeclared one, a wrong type -- fails the test.
So a contract that gains a required member fails this suite until the documentation shows it.

The path is `CreateBookOperation.PATH`, by name.
A path parameter is filled into `PATH` the same way, by position:

[source,java]
----
include::{example-dir}/src/documentationTest/java/com/example/books/documentation/BooksDocumentationTest.java[tag=get-book]
----

The REST Docs emitter generates field descriptors only, not path-parameter descriptors.
The example describes `+{id}+` in the text of its page instead.

== Step 4: An error response, with a meaningful invalid value

An error worth showing is one a reader might make: an ISBN-10 where the contract asks for an ISBN-13.

[source,java]
----
include::{example-dir}/src/documentationTest/java/com/example/books/documentation/BooksDocumentationTest.java[tag=create-book-invalid]
----

The service answers:

[source,http]
----
HTTP/1.1 400 Bad Request
content-type: application/problem+json
Content-Length: 173

{
  "title" : "The request does not match the contract.",
  "status" : 400,
  "errors" : [ {
    "field" : "isbn",
    "message" : "must match \"^97[89][0-9]{10}$\""
  } ]
}
----

Not `a` for a title, not `unexpectedMember`: those prove a rule, and are the contract tests' business.

== Step 6: The page that includes only these snippets

`src/docs/asciidoc/index.adoc` is the published page.
It includes each snippet of this suite by its directory -- `+include::{snippets}/create-book/http-request.adoc[]+` -- and nothing from `generated-service/` or `generated-stubs/`, where the contract tests write theirs.
link:{example-dir}/src/docs/asciidoc/index.adoc[The page's source →] is short enough to read whole.

[source,groovy]
----
include::{example-dir}/build.gradle[tag=asciidoctor]
----

`asciidoctor` depends on the documentation suite and nothing else, so a contract test never runs to produce the page.
`failureLevel = 'WARN'` makes a missing snippet fail the build, instead of leaving a hole in the page.

[source,console]
----

----

The page is `build/docs/asciidoc/index.html`.

[#result]
== What you have now

* A documentation suite, against the real service, with values a reader recognises.
* Paths, bodies and field tables from the generated classes, so the page fails the build when it drifts from the contract.
* A page that includes this suite's snippets only, and never a contract test's.
