= The safety net: hand-written reference classes

The reference implementation's hand-written `testSchemaCommon` classes, and what they return from `body(...)`.
The generator is measured against these; `SOURCE.properties` names the commit they were copied from.

[source,console]
----
# The repeatable comparison. Add -PreferenceRepository=<SoftwareEngineeringDoneRight-Code checkout>
# to also check the copies against the recorded commit; without it that check is skipped.
./gradlew verifyHandwrittenFixtures

# Only when SOURCE.properties is deliberately moved to a new commit. Review the diff.
./gradlew recordHandwrittenFixtures
----

== Strict: must hold

`bodies.json`::
Every recorded `body(...)` output.
These bodies are real data that `testSystemWireMock` serves, so generated output that differs is a regression.
Each case's `comparison` says how generated output is held to it:
+
[horizontal]
`strict-bytes`:: Byte for byte. Every case except `UserV1`.
`json-equal`:: The same JSON value, formatting ignored.
`UserV1` only: its hand-written body is indented over several lines while every other body is compact, and the repository owner decided generated output is compact.

The `testContract` and `testContractWireMock` suites passing with generated classes substituted is the other strict criterion.
It is checked in the reference implementation, not here.

== Advisory: a lower bound and a style reference

Everything under `src/handwritten` other than what `body(...)` returns: the field descriptors, their optionality, their descriptions, the class layout and visibility, and `contract-error-descriptions.properties`.

The generator must cover at least what these cover.
Anything more is a feature.
Any other difference is reported, not reconciled silently in either direction: it is either a generator bug or a gap in the hand-written class.

== What the inputs are

The literal arguments at the reference implementation's `body(...)` call sites, plus one case per class with a quote and a backslash, which is all the hand-written `JsonText.escape` handles.
Control characters are deliberately absent: the hand-written escaping passes them through, producing invalid JSON, and recording that as strict would oblige the generator to reproduce it.
