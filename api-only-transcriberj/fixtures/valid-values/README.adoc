= Valid-value fixtures

What valid-value generation -- `requiredBody()`, `fullBody()`, `requiredRequest()`, `fullRequest()` and `noBodyRequest()` -- is held to.
Every value is checked against an independent JSON Schema 2020-12 validator (networknt, with ECMA-262 patterns by joni), a test-only dependency that never reaches the plugin's classpath.

[cols="1,3",options="header"]
|===
|Path |What it is

|`corpus/keywords.yaml`
|Written for these tests: every rule of the README's _How a value is chosen_, in isolation and in the combinations that matter.
Each component's comment says the value its rule gives.

|`corpus/exclusive-3.0.yaml`
|The OpenAPI 3.0 boolean `exclusiveMinimum` and `exclusiveMaximum`, which 3.1 writes as numbers.

|`corpus/unsatisfiable.yaml`
|One component per condition that leaves no valid value, or none the generator can find.

|`corpus/parameters.yaml`
|Path, query and header parameters, the ones not supported yet, the ignored headers, and request bodies.

|`golden/<contract>.json`
|The machine-readable report of each reference contract under `../contracts`, indented.
A change to value generation shows up here as a diff to review.
Re-record with `./gradlew recordValidValuesGolden`.

|`baseline-sources.sha256`
|The hash of every source generated before valid values were, from `main` at 1172661: the reference contracts, with and without `generateDocs` and a description bundle, and the corpus.
Each source generated now, with the valid-value members stripped, must hash the same: every existing member stays byte for byte what it was.
Re-record with `./gradlew recordBaselineSources`, for a deliberate change to existing members only.
|===

The corpus contracts are hand-written, not built by the Publisher, and are free to change with the tests; the reference contracts under `../contracts` are not.

The oracle reads each document as the plugin does, with two rewrites: a `format` beside a `pattern` is dropped, as the pattern wins; and a 3.0 boolean exclusive bound becomes the 3.1 numeric one.
